# 精校轮：先准确，再通顺，最后才是文气

第 4 步的对账管"在不在"，[semantic-review.md](semantic-review.md) 管"对不对"，[translation-rules.md](translation-rules.md) 规则 3 管"顺不顺"。三件事都有规则，缺的是**顺序、门禁与留痕**——尤其缺一条：改顺的动作为什么不会把已经查对的地方改坏。

这一份讲的就是这条线。

## 为什么要独立成一轮

润色是整条流程里**唯一一处"改对的地方可能改出新错"**的环节。对账、语义审读、公式归一都只会让稿子更接近原文；只有改写会在信息量上做加减，而且做错的时候中文读起来更顺——错译读着顺，是最难被发现的那一类。

所以不能边读边改、改完就算。要拆成四个动作，每个动作带一次门禁：

```
候选（只记录，不动正文） → 裁决（回原文定去留） → 最小编辑（按裁决改） → 复检（重跑机械项）
```

最保守的交付是**只交候选表、不动正文**：代价是稿子不够顺，但不会更不准。

## 三层分工：哪一层谁说了算

| 层 | 内容 | 判据 | 谁有决定权 |
|---|---|---|---|
| L1 保真 | 量、否定、模态、时点、指代、术语、引文、数字、公式 | 与原文是否等价 | **原文**。术语表、前译、惯例都不是权威 |
| L2 句法 | 语序、断句、主从、虚词、名词化→动词、被动→主动、代词还原 | 中文读者能否不回看英文 | 译者。这一层完全属于译者 |
| L3 文气 | 句长节奏、用词轻重、重复与变奏、评语位置 | 是否同一副嗓子、是否像学术文本 | 译者，但要服从已知的风格约定 |

**顺序不可倒。** L1 没过就做 L2，等于把错译润色成读起来很顺的错译；L2 没过就做 L3，是在给病句配节奏。三层同时看的结果是注意力全落在别扭的句子上——而错译恰恰不别扭。

L3 是"雅"的落点，也是唯一可以整层跳过的一层。**跳过它是可以交付的；跳过 L1 不行。**

## 第一步：候选——只记录，不动正文

候选有三个来源，互不替代：

```bash
# 1) 脚本能筛的：术语不一致、候选术语、数值
python scripts/semantic_audit.py <stem>_正文.md <stem>_正文_zh.md -o _work/<stem>_数字核对.md
python scripts/review_queue.py <stem>_原文.md <stem>_zh.md --glossary _work/<stem>_术语.csv \
    --manual _work/<stem>_人工待校.csv -o _work/<stem>_待校对.md
# 2) 中文病灶：按句列出可疑处，不自动改
python scripts/style_check.py <stem>_zh.md --style _work/<stem>_风格.md -o _work/<stem>_语体可疑.md
# 3) 语义偏离：独立上下文子任务逐段三态，见 semantic-review.md
#    第 4 步已经做过就直接导入结果，不重跑；本轮新增的是 L2／L3
```

**候选落在精校候选表里，不要散在对话里**——散着就无法统计覆盖率，也无法回退。三张表各管一段，不要合并，也不要让同一个决定在两处并行维护：

| 文件 | 收什么 | 谁写 |
|---|---|---|
| `_work/<stem>_人工待校.csv` | 翻译过程中遇到、**要人定**的四类决定（多译法、歧义、学派立场、原文疑误） | 第 3 步翻译时随手写 |
| `_work/<stem>_待校对.md` | `review_queue.py` 汇总的清单，给人读、留「你的意见：」 | 脚本生成 |
| `_work/<stem>_精校候选.csv` | 本轮审读发现的**要不要改**的意见，带层与裁决 | 精校时写 |

`escalate` 的条目转写进人工待校表，然后只在那里裁决——两处都挂着同一个问题，最后必然出现一处改了另一处没改。

```csv
段号,层,类型,原文片段,现译,建议,依据,裁决,动作
§12,L1,偏离,"not all firms can realize…","所有企业都无法实现…","并非所有企业都能实现…","not all ≠ none","confirm",
§12,L2,生硬,"—","资本对劳动过程的控制的实施依赖于…","资本实施对劳动过程的控制，依赖于…","名词化→动词","confirm",
§31,L3,节奏,"—","(整段)","(建议前半句收紧)","三个短句连排，与上下文基调不合","dismiss",
```

列的含义固定，不要加列：

- **层**：`L1`／`L2`／`L3`。层填错，后面的门禁就失效。
- **裁决**：`confirm`（改）／`dismiss`（不改，`依据` 列写为什么）／`escalate`（交人，见第 5 节）。
- **动作**：确认后填 `review_apply.py` 的决定键（`text:…`／`term:…`），留空表示还没执行。

**L3 候选要克制。** 一段话改三次可以三次都通，这不构成"第三种更好"的证据。同一段累计被提了三条以上 L3 候选，先怀疑是原文本身罗嗦或自己的判据不稳，不是稿子不好。

## 第二步：裁决——source decides

每条 L1 候选都要回原文，而且只认一件事：**原文这句话到底说了什么。**

四种常见的错误裁决，都要挡掉：

| 诱惑 | 为什么不行 |
|---|---|
| "术语表是这么定的，所以译法对" | 术语表定的是**词形**，不是这句话的**意思**。`realization` 在 `realization of surplus value` 里是实现，在 `realization of a tendency` 里可能是认识 |
| "前面十处都这么译，这处也照旧" | 一致性和正确性是两件事。错一处和错十处只差错的规模 |
| "作者在这里用词不严谨，我按他的本意译" | 那是替作者改。原文含糊就译成含糊，写进"原文疑点" |
| "读者会误解，加半句限定更清楚" | 加的是你的判断，不是作者的信息。属于"增" |

反过来，**`dismiss` 也要写依据**。空着的驳回和没查过没有区别——下次接手的人无法判断这条是被审过还是被跳过。

L2 候选不需要回原文，只需要遮住英文读一遍中文：必须回看英文才懂的，是没译完；一口气读不完要找主语的，是该拆没拆。

## 第三步：最小编辑

改了就要能复核。三条硬约束：

1. **只改被裁决指出的那一处。** 顺手改相邻句会让 diff 里混进未裁决的改动——复核时无法分辨哪一处是查过的。
2. **跨段的事一律不做。** 不合并两段、不拆一段、不挪句子到邻段。段界是对账的基准，动它等于让第 4 步的结论作废。
3. **不进正文的东西不许碰。** `[^n]` 标记、`$$…$$` 块、行内 `$…$`、`(Shaikh, 2016, p. 42)`、`<!-- REFS-ORIGINAL … -->`、`#` 与列表符号、图片路径。这些不是文字，是结构。

**diff 要逐条过目，不要只看条数。** 一个可用的自查：改动行数超过候选条数的三倍，说明改过头了——多半是顺带重写了一段。

**一段 L1 偏离超过三处，重译比逐处改便宜**，而且更不容易漏。那种情况退出精校轮，回第 3 步重译这一段，重译后仍要进本轮的候选表登记"整段重译"。

## 第四步：复检——润色之后必须重跑

L1／L2／L3 任何一层动过，都按第 4 步重跑一次，不许"只是改了措辞"就免检：

```bash
python scripts/normalize_math.py <stem>_zh.md --inplace
python scripts/zh_quotes.py <stem>_zh.md --inplace
python scripts/fidelity_check.py <stem>_原文.md <stem>_zh.md --glossary _work/<stem>_术语.csv --strict
python scripts/semantic_audit.py <stem>_正文.md <stem>_正文_zh.md -o _work/<stem>_数字核对.md
```

改写最常撞坏的四样，脚本各有分工：**块结构**（合并/拆分/漏段）由 `fidelity_check.py` 拦；**数字与页码**由 `semantic_audit.py` 拦；**术语是否被顺手换掉**由 `--glossary` 拦；**引文是否还是原话**要在动过引文时重跑一次 `marx_quotes.py`（`--source`、`--target` 同第 4 步），没有引文可跳过。

改过引文、数字、限定词的地方，**要回原文再核一遍**——脚本只保证"和改前一样"，不保证"和原文一样"。如果某处是因为原文理解错了才改的，那属于语义层返工，不是精校。

## 第五步：什么时候交给人

只有四类 `escalate`，与第 5 步同口径：语义歧义、术语未定、学派立场、原文疑误。**其余一律自己定**——句子怎么断、语序怎么调、虚词加哪个，问用户等于把工作退回去。

同一处被两个来源给出**互相冲突的建议**时（比如术语表要 A、语义审读要 B），不要挑一个执行，也不要折中成第三种：进 `_work/<stem>_精校冲突.csv`，两条建议各自的范围与代价写清，交人裁决。冲突的价值不在"选哪个"，而在暴露"这里本来就有两种读法"。

## 完成判据

- 候选表里**每一段都有结论**，不是"抽了几段觉得还行"。收据写成段号区间，让人一眼看出有没有跳段：

```
精校覆盖：§1–§58 全部有结论（L1 偏离 5、疑点 2、L2 26、L3 9、驳回 7）
```

- 所有 `confirm` 都已执行并复检通过；所有 `dismiss` 都写了依据；所有 `escalate` 都已交人。
- `fidelity_check.py --strict` 通过，`semantic_audit.py` 的每一条都回过原文。
- 交出去的说法是"**逐段查过，这一层没有发现偏离，覆盖 §1–§58**"，不是"通读后确认准确"。前者划定了范围与段数，后者什么也没说。

**查完不等于译好。** 只等于按这份清单看，没有发现问题。真正读得懂的人一眼看出的毛病，可能仍在里面——这也是为什么 L3 值得做，但永远排在 L1、L2 之后。
