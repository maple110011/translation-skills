# 公众号版：可直接粘贴的排版稿

```bash
python scripts/build_wechat.py <stem>_zh.md <输出目录>
```

产出两份：`wechat_article.html`（完整网页，顶部有"复制全文"按钮，粘进编辑器即带样式）与 `wechat_article.md`（纯文本备份，日后改字用）。

**图片**：裸 Markdown 图（`![alt](path)`）与**一行多图**都会排成 `<img>`，并排图用 `inline-block` 横排（不能靠 flex，公众号编辑器会剥掉 `display:flex`）；宽度必须给 **px**，写百分比会被 `self_check()` 拦下来——公众号不吃百分比宽度。旧版只认 HTML 表格里的 `<img>`，裸图整行会被当普通文字留在版面上，等于整篇没图。

## 一、脚本按发布口径做六件事

规则写死在代码里，不需要每次交代：

1. **去掉标题与作者行**——H1 与 front matter 里的 title 都不上版面；作者行（`Deepankar Basu、Cameron Haas 和 Thanos Moraitis` 这种纯人名行）同样删掉，作者由「文献来源」那一行与公众号主体承担。两者都只在公众号通道删，Markdown 交付稿里留着。
2. **去掉参考文献整节**——公众号里放一百条英文著录没有意义，读者需要的是原文 DOI。
3. **脚注改就地引用框，正文保留上标**——每条按编号**挂到它所注的那一段之后**，用左侧竖线的框呈现；同时**正文里的上标标记要留着**（转成带色的 `span`）。只做框不做标记，读者不知道这句话有注；只做标记不做框，注释得跳到文末再跳回来，等于没注。上游统一交正文内联 `[^n]` + 文末 `[^n]:` 定义（第 1 步 `footnote_recover.py --apply` 的产物），脚本靠正文里的 `[^n]` 定位段落；**没有正文标记的定义只能堆到文末**，`audit_notes()` 会把它报成「定义未进版面」。脚本仍兼容历史稿：正文 `<sup>n</sup>`、`## 脚注`／`## 注释`／`## Notes` 节下的 `1.`、`(1)`、`-`、`注 1`、`<sup>1</sup>` 条目、折行与无空行连排、`<!-- FOOTNOTES-RECOVERED -->` 标记都认。
4. **开头两行信息**——`翻译&编辑：X`（同一人时合并写，不同人时写"翻译：X　编辑：Y"），换行接 `文献来源：` 后跟 APA 7 条目（`作者 (年份). 题名. 刊名, 页码.`）。用浅灰小字压在正文之上，与正文之间留一条细线。**题名只给原文，不加中译方括号、不挂 DOI**——公众号读者要看的是这篇东西是谁写的、发在哪；中译题名与 DOI 属于参考文献体例，两者混在一行会读成半中半英。
5. **公式变成浏览器里渲染的内联 `<svg>`**——微信不认 MathJax/KaTeX 脚本，`$…$` 粘进去就是字面美元符。脚本输出 `<span class="woap-math" data-latex>` 占位符，页面加载时由本地 MathJax 3 渲染成行内 SVG，复制按钮取的是渲染后的 DOM。细节见下节。
6. **表格压进 637px，不做横滑**——微信里 `overflow` 无效，横向滑动做不出来。四列表格只能按 px 分配：首列 88px 放"控制概念"这类标签，其余三等分各 183px，字号降到 13px。

## 公式：为什么只能在浏览器里渲染

微信图文编辑器会过滤 `<script>`，MathJax / KaTeX 在公众号里跑不起来；`$…$` 原样粘过去就是一串美元符。可行方案只有一条：**先在浏览器里排好版、变成内联 `<svg>`，再把渲染后的 DOM 复制过去**。下面每条约束都是踩出来的（逆向墨滴 v0.4.3 + 真实微信 A/B 实测）：

| 约束 | 做法 | 不这么做会怎样 |
|---|---|---|
| 字形自带，不依赖共享定义 | MathJax `svg.fontCache:"none"` | 微信剥离共享 `<defs>` 后公式缺字 |
| 不用 `transform` | 墨滴保留 transform，但在 SVG 末尾追加一个空 `<g>`，让微信删它而不是删字形 | 微信删掉含 `transform` 的 `<g>`，字形全叠到原点 |
| 尺寸写 `style` 不写属性 | `width`/`height` 挪进 `style` | 属性被过滤，公式按默认大小排 |
| 行内公式嵌在 `<span>` 里 | `<span class="span-inline-equation"><span class="inline-equation" data-formula="…">svg</span></span>` | 行内公式脱离正文流 |
| **块级公式必须是 `<p>` 内嵌行内 svg** | `<p class="block-equation" style="text-align:center;overflow-x:auto;margin:0.8em 0">svg</p>` | 换成 `section`/`div` 会被 ProseMirror 对象化，**前后各多一个空行**（六组结构实测，只有这一种干净） |
| svg 保持行内 | 不设 `display:block`、不设 `margin:0 auto` | 同上，触发对象化 |

**产物与依赖**：MathJax（`scripts/assets/mathjax/tex-svg-full.min.js`，2.2 MB）与包装脚本（`scripts/assets/wechat-mathjax.js`）**内联进 HTML**，成品是 2.3 MB 的单文件——双击就渲染，拷到哪都不丢，也不走 CDN（公众号排版常在离线或内网做，外链一挂页面就只剩空占位符）。代价是 HTML 变大、打开时多等一两秒。

**渲染失败的降级**：某条公式让 MathJax 抛错时，占位符还原成原始 `$…$` 并在控制台报数，**不静默丢公式**。真遇到（宏包不支持、`\begin{cases}` 写错），回源头改 TeX，别指望公众号端兜住。

**两个已知限制，交付时要跟用户讲**：

1. **粘进公众号后再编辑，公式可能丢**——墨滴自己也这么说。要改就改 `wechat_article.md`，重新生成、重新粘贴。
2. **公式多的长文，Chrome 里粘贴可能卡住**（Firefox 更稳）。几百条公式时先在 Chrome 试一小节，卡就换 Firefox。

`--math=off` 关掉公式渲染，只出文字版（纯文字稿，或排查占位符问题）。

## 二、白名单：为什么用 class 写样式一定会掉

公众号编辑器把粘进来的 HTML 过一遍**白名单过滤**：保留结构标签与写在元素 `style=""` 里的样式，**删掉 `<style>` 块、`<link>`、全部 class 与 id**，并过滤掉一批属性。所以"本地好看、粘过去散成裸文本"的唯一原因是样式没内联——不是浏览器的问题，也不是复制方式的问题。

| 约束 | 做法 | 为什么 |
|---|---|---|
| 样式全内联 | 每个标签带完整 `style=""`，不生成样式表 | `<style>` 与 class 一律被删 |
| 容器用 `<section>` | 不用 `<div>` | section 在白名单里，底色与圆角更容易保住 |
| 单位用 px | 宽度、边距、字号都写 px | 百分比与 `vw` 在窄屏会被压变形甚至被过滤 |
| 避开布局属性 | 不用 `position`、`flex`、`grid`、`transform`、`box-shadow`、`overflow` | 前四个会被清除；`overflow` 无效，横向滑动做不出来，表格只能压到 637px 内 |
| 上标用 `<span>` | `font-size:11px;line-height:0;vertical-align:super` | `<sup>` 不在稳定白名单，可能退化成普通数字；`line-height:0` 防止撑行高 |
| 不用 CSS 变量 | 颜色写十六进制字面值 | `var(--x)` 不解析 |

正文区实测可用宽度约 **637px**（编辑器 677px 减去两侧内边距）。四列表格按 `88px + 183px × 3` 切，首列刚好放"控制概念"四个字，其余均分；靠 `%` 分配会被压成一列。

## 三、两道自检

`build_wechat.py` 的 `self_check()` 会拦住上面每一条，输出前自检，不过就报错不写文件。同一次自检里 `audit_notes()` 另管内容完整性：抽出脚注却一条没进版面、某条只有定义没上版面、输出残留字面 `[^n]` 或裸 `<sup>`，同样是硬错误；正文上标找不到定义、定义找不到上标只作提醒。**样式通过不等于内容通过**——只查样式的那版曾让 `[^n]` 稿子静默丢光脚注还报"自检通过"。

## 四、粘贴方法（两条都对，按钮更省事）

1. 浏览器打开 `wechat_article.html`，点顶部"复制全文"，到编辑器 `Ctrl/⌘+V`。脚本只把根 `section` 的 `outerHTML` 写进剪贴板，按钮与页面底色不会带进去。
2. 编辑器右上角开**源码模式**，把 `wechat_article.html` 里 `<section id="wx-root">…</section>` 整段贴进去，再切回富文本视图。

粘完在手机上预览一次。少数情况下底色仍掉，用壹伴或 135 编辑器中转一遍即可——它们做的就是同一件事（CSS 内联化），只是多一层兜底。

**PDF 与公众号版是两条独立发布分支，都以同一份 `[^n]` 译稿为源**，互不干扰。PDF 侧见 [pdf-latex.md](pdf-latex.md)。
