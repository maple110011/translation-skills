# 语义审读

结构对账管得住"有没有少"，管不住"意思有没有偏"。这一份讲怎么查后者。

## 为什么不列细则给脚本跑

这里记一笔实测，免得下次又想用词表解决：`semantic_audit.py` 最初查四类（数字、否定、限定、逻辑），跑三篇真实译稿，Saros2014 报 11 处，逐条核完 **6 到 8 处是误报**：

| 报了什么 | 实际 | 根因 |
|---|---|---|
| `thus` 未译因果 | 原文是 **thus far**（至此） | 同形异义 |
| `Since` 未译因果 | 原文是 **Since...first introduced**（自从） | 同形异义 |
| `must` 缺失 | 译作"还**须**定义" | 中文用一个字 |
| `may` 缺失 | 译作"都**能**得到表示" | 省略情态是合法的 |
| `10,000` 丢失 | 译作 `10000` | 中文不写千分位 |

补词表能修掉后三条，修不掉前两条：同一个词在不同位置承担不同语义功能，字符串匹配看不见这个差别。**所以限定、否定、逻辑、量词这几类只能读，不能匹配。**

脚本只留一类它真能做对的：**数值**（含页码区间）。数字错是硬错，且不受语言习惯干扰。归一化后 `10,000`、`10 000`、`10000`、`5 per cent`、`5%` 都算同一个值。

## 怎么读

逐段，一次一段，只给三种结论之一：

| 结论 | 什么时候用 | 要写什么 |
|---|---|---|
| 通过 | 意思、范围、强度都对得上 | 不用写 |
| 偏离 | 能指出译文的说法会让读者理解成另一个意思 | 原文片段 + 译文片段 + 一句话说差在哪 |
| 疑点 | 可能偏离，但要作者判断 | 两种读法各是什么，代价分别是什么 |

**不给"整体准确"这种结论。** 一句"通读后未发现明显偏差"背后可能是查了 120 段，也可能只看了开头三段，读的人分不出来。逐段记，最后给出段数与偏离数。

## 查什么

下面是**提示**，不是封闭清单——真实错误常常不在里面。按"会不会让读者理解成另一个意思"排序：

1. **量的范围**：`all`／`some`／`most`／`many`／`few`／`not all`。政经文献里"并非所有"被译成"所有都不"，整段论证就反了
2. **否定辖域**：`not because A but because B` 否定的到底是哪一半；`it is not that...` 后面才是真主张
3. **情态与承诺强度**：`may`／`must`／`should`／`would have`（反事实）。`would have been` 译成"曾经是"，虚拟语气就没了
4. **比较方向**：`higher than`／`less than`／`the same as`，谁高谁低有没有译反
5. **时态与时点**：`has been`／`had been`／`will have`。马克思主义文献里"已经完成"与"正在发生"分得很细
6. **条件与让步的范围**：`if`／`unless`／`provided that` 管到哪一句，有没有被放大或缩小
7. **连接词的具体义**：`while`（当……时／虽然）、`since`（自从／因为）、`as`（当／因为／正如）、`thus far`。这几个词按"常见义"译，十次有三次是错的
8. **修饰语归属**：`the exploitation of labour by capital`——谁剥削谁；长定语挂在哪个中心词上
9. **指代**：`this`／`these`／`it`／`they`／`former`／`latter` 指向哪个名词短语
10. **术语在句中的意思**：不是"用了约定译法"，而是"这个概念在这句话里是不是这个意思"。`realization` 在 `realization of surplus value` 里是"实现"，在 `realization of a tendency` 里可能是"认识"
11. **引文逐字**：直接引语有没有增删字词；引文页码有没有挪
12. **段与段的论证**：上一段的结论，这一段是承接、转折还是限定

数字不用在这里查，`semantic_audit.py` 已经筛过一遍；但仍值得抽两三段验一下脚本没漏。

## 举证格式

三条缺一不可：

```
§47  偏离
原文: "not all firms can realize the surplus value they produce"
译文: "所有企业都无法实现它们生产的剩余价值"
差在: not all → 所有都不，量的范围从"部分"变成"全部"
```

只写"这句译得不准"没有用——作者得回去自己找一遍，等于没查。**贴出两段原文**，判断就能在十秒内做完。

## 防自我确认

同一个模型刚译完再让它审自己的稿，倾向于说"整体准确"。这不是态度问题，是它已经形成了"我当时是这么理解的"这条路径。四种办法，按效果排序：

**1. 开一个独立上下文的子任务。** 当前环境支持派生 subagent 时，这是最省力的一种：交给它原文与译文，不给它翻译过程、术语决策、为什么这么译。它看不到这些，也就没有那条路径。要点：

- 材料只给"原文段落 + 对应译文"，成对排在一起（省得它自己去对齐）
- 让它先读本文件，按三态结论与举证格式执行
- 要求逐段列段号，从段号列表能看出它有没有跳段
- 结果写成文件，不接受"整体准确"这种对话式总结
- 可以指定不同的模型或推理档位；换不换都行，独立上下文已经消掉大半问题
- **它也可能编。** 报上来的每条都要回原文核一遍，尤其是"疑点"——那是它自己也没把握的地方

实测一次：Passarella2015 §20–40（21 段）交出去，回来 0 偏离、1 疑点。疑点是真的——`given the organic composition of capital` 译作"就资本有机构成而言"，丢掉"在 q 既定时"这层限定，而 q 正是式 (5)/(5bis) 里的参数。这类问题不在任何词表里，两种读法都通，只有结合 §31 才能判断。

**2. 分段做，不要一次给总评。** 一次看十段，比一次看一百段认真得多。

**3. 从后往前读。** 打掉"顺着译文读下去"的惯性，最后几段通常是质量最松的。

**4. 抽样回译。** 随机取五段译回英文，与原段并排看。结构性的理解偏差在回译里会放大，比逐句对照更容易发现。

前三种针对的是"路径依赖"，第四种针对的是"模型本身的理解偏差"——子任务不能消除后者，底层还是同一个模型。所以抽样回译不要省。

## 什么时候算查完

- 每一段都有结论，不是"抽查了几段觉得还行"
- 所有"偏离"都已修掉或明确保留（保留要写理由：原文如此、作者用法特殊）
- 所有"疑点"都交给了用户，并附了两种读法的代价
- 数字核对清单（`_work/<stem>_数字核对.md`）里的每一条都回过原文

**查完不等于译对。** 只等于"按这十二类看，没有发现偏离"。真正读得懂的人一眼看出的问题，可能仍然在里面。
