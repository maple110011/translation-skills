# 图表：就近归位与图片版式

正文里 `Table 1 summarizes…` 与表本身的关系，在 PDF 里由排版决定，在 Markdown 里要由你重建。这份文档管两件事：**图表的所在位置**、**图片的内部版式**。两件事的边界不同，别混。

## 一、按"首次提及"归位

期刊的排版逻辑是先排满正文、再找地方放图表：出版社为了让版面不留白，会把表格挪到两三页之后，把图挪到章末。MinerU 忠实地按**版面位置**提取，于是提取稿里常出现"这里写 Table 1 summarizes…，表却在三百字开外"。译成中文后段落更长，读者滚动两屏才看到表，已经忘了表讲什么。

**规则：图表跟着"第一次提到它的那一段"走，就近落位。**

1. **先找提及句，不要找图表块。** 搜 `表 N`／`图 N`／`Table N`／`Figure N`，找出正文里第一次提到它的那段。图表应当落在这段之后（同一节内、紧跟该段）。
2. **连同引出句一起搬。** 表前那句"表 1 按各位作者概括了…"属于表的引入语，和表是同一块内容；只搬表、留下引出句，等于让这句话悬空。
3. **跨节搬要连标题一起搬。** 图表的自然归属可能落在下一节（如"表 1 概括本节三种类型"而表被排到了下一节标题之后）。把标题、表体、引出句一起移到合适位置，**不要留下一个空的节标题**。
4. **一处也不能丢，顺序不能乱。** 搬完重跑 `fidelity_check.py`：表格行数必须不变，块序列必须仍然对得上（对不上说明搬的时候连正文段落一起动了）。

### 改了位置，对账基准也要改

`fidelity_check.py` 比的是块序列：源文件里表在 A 处、译文里表在 B 处，必然报"块级结构不一致"。做法是生成一份**按发布版式重排过的源文基准**（`_work/<stem>_原文_发布口径.md`），在这份副本里把图表挪到与译文相同的位置，然后用它做基准。

**基准只服务于校验，不改原文文件本身**——原文是证据，不能为了"过校验"去动它。发布稿口径的删节（作者名、致谢等，见 [delivery.md](delivery.md)）也在这份副本里一并处理。

## 二、多联图与图片尺寸：按原刊版式还原

MinerU 把原刊的"一行三栏图"识别成三个独立 `image` 块，`full.md` 里就是三条各自独立的 `![…](…)`。照着渲染，PDF 里就是三张各占 0.93 栏宽、上下堆叠的图——**一页塞一张，图注还被拆散**；附录里只占半栏的图同样被拉满整栏。这两件事一次解决：

```bash
# 1) 按 content_list 的 bbox 分组 + 量宽，并把同组多图合成 md 里的一行
python scripts/figure_layout.py _work/extract -o _work --md <stem>_zh.md --apply

# 2) 出 PDF 时把版式清单交给 md2tex
python scripts/md2tex.py <stem>_zh.md _work/pdf/paper.tex --fig-meta _work/图片版式.csv --pdf
```

`figure_layout.py` 只做两件事：**同页同排的图并成一行**（竖直重叠过半即判同排），**按 `bbox 宽 / 该页最宽文本块` 给出每张图的原刊占比**。它产 `_work/图片版式.csv`，并顺手把夹在图之间的子图标签（"含类别特征""归一化 ROC AUC"）收成一行小字放在图与图注之间——**别手工删那些标签**，它们是 MinerU 从图里切出去的文字，图片本身没有。

栏宽必须取**该页最宽文本块**：附录页只有标题和轴标签，取中位数会把 27% 算成 68%，宽度反而更离谱（踩过）。已经是 `<table><td>` 写法的多联图会被跳过，**两种写法不要混用**。

`md2tex --fig-meta` 用这份占比定 `width=N\linewidth`；多联图按各栏真实比例分配（实测 41%/27%/27%），不是等分。没有这份清单时退回旧的「单图 0.93、多图等分」，附录的小图就会继续偏大。

图号也在这条链上：浮动对象重定位后，出现顺序与原刊编号不一致，`\caption` 自增出来的号会和正文"在图 6 中"打架。`md2tex` 从 `**图 N**` 里读出原刊编号并 `\setcounter{figure}`，PDF 图号跟着译文走。渲染端的其余细节（图片/裸图识别、超宽表格、`minipage` 底对齐）见 [pdf-latex.md](pdf-latex.md)。
