# 交付前检查

脚本能查的（结构、引用、公式、未译段、段落长度异常）由 `fidelity_check.py` 负责，承重细节由 `semantic_audit.py` 先筛一遍。这份清单只管脚本查不出来的部分。分四遍过，不要一遍全看——四种注意力互不相同，混在一起就都使不上。

**先认清脚本的边界。** 块级结构对账能发现"整段不见了"和"多出一段"，发现不了段内的增删；段落长度启发式能提示段内漏译，但会误报（表格段、人名罗列段、密集记号段天生比例异常），每条都要回原文确认。术语对不对、中文通不通、论证有没有译反，脚本一概不知。**脚本全绿不等于译文合格。**

---

## 第一遍：对着原文读，只查"少没少、多没多"

逐段对照，不看中文通不通顺，只看信息是否一一对应。

- [ ] 每一段都有对应译文，没有"看着像重复就跳过"的段落
- [ ] 段内没有整句遗漏，尤其是括号里的补充说明、破折号后的插入语
- [ ] 没有新增原文没有的事实、评价、背景、因果判断
- [ ] 没有合并段落，也没有拆段
- [ ] 数字、年份、百分比、样本量逐个核对（`1973` 不是 `1873`）
- [ ] 页内交叉引用（"见第 3 节""如表 2 所示"）指向的编号与原 PDF 一致
- [ ] 脚注数量一致，内容对得上，位置没挪；第 1 步的 `_脚注体检.md` 结论为 PASS（MinerU 常整批丢脚注，块级对账查不出来）
- [ ] 参考文献表已原样拼回（`split_refs.py --restore`）：条目没有被译成中文、没有重排、没有补造 DOI 或页码；书目在哪一节后面，位置与原稿一致
- [ ] 书目之后的附录、作者简介、致谢照常译了，没有被当成书目一起切掉
- [ ] 图注、表注都译了，且没有并进正文

## 第二遍：语义——对着原文，查"意思有没有偏"

第一遍查的是"在不在"，这一遍查"对不对"。数字由 `semantic_audit.py` 先筛过；**否定、限定、量词、逻辑这些不要指望脚本**——试过，误报过半（`thus far` 被当因果、"须"被判漏译），只能读，见 [semantic-review.md](semantic-review.md)。

逐段读，只给三种结论：通过／偏离／疑点。偏离必须贴原文与译文两段，否则等于没查。

**读的人最好没参与翻译。** 能让独立子任务做就交给它（只给原文与译文，不给翻译过程），或者隔开一段时间自己读——刚译完就读自己的稿，眼睛会顺着原路走。见 [semantic-review.md](semantic-review.md)。

- [ ] 量的范围：`all`／`some`／`most`／`few`／`not all`——"并非所有"没有被译成"所有都不"
- [ ] 否定辖域：`not because A but because B` 否定的是哪一半
- [ ] 情态与承诺：`may`／`must`／`should`／`would have`——反事实没有被译成陈述
- [ ] 比较方向：谁高谁低，`less than` 没有译反
- [ ] 时态与时点：`has been`／`had been`／`will have`，"已经完成"与"正在发生"没混
- [ ] 条件与让步的范围：`if`／`unless`／`provided that` 管到哪一句，没有放大或缩小
- [ ] 连接词的具体义：`while`／`since`／`as`／`thus far`——按常见义译的地方，回头看原文是不是另一个意思
- [ ] 指代：`this`／`these`／`it`／`they` 指哪个名词短语，中文里换成了明确的词
- [ ] 修饰语归属：从句、分词短语挂在哪个中心词上，没有被挪位
- [ ] 术语：不是"用了约定译法"，而是"这个概念在这句里是不是这个意思"
- [ ] 引文逐字：直接引语没有增删字词，页码没挪
- [ ] 段间论证：上一段的结论，这一段是承接、转折还是限定，转折没被译成顺承
- [ ] `semantic_audit.py` 报的每一条都回了原文

**这一遍不看中文通不通顺。** 通顺是下一遍的事。两件事一起看，注意力会全落在别扭的句子上，而错译往往读起来很顺——这是它最难被发现的原因。

## 第三遍：中文本身

这一遍不看英文，只读中文。读不懂、需要回看英文的地方，就是没译到位。

- [ ] 通读一遍，句子是否像中文写的
- [ ] 把第 1 段和最后一段并排读：自称、论证动词口径、句长、插入语处理，是不是同一副嗓子——风格漂移单看一处永远合格，只有并排看才发现
- [ ] `_work/<stem>_风格.md` 里列的禁用词，全文一次都没出现
- [ ] 一个段落里"的"不超过 6 次
- [ ] 没有连续的"被"字句（`被……所……`）
- [ ] 没有"进行/作出/加以 + 名词"的滥用
- [ ] 没有连续三句以"这""该""其"开头
- [ ] 长句断开了，一句话说一件事
- [ ] 代词（它、此、前者、后者）在可能歧义处换成了具体名词
- [ ] 术语与前文一致，包括复数、所有格、缩写形式
- [ ] 没有"值得注意的是""综上所述""由此可见"这类填充语（除非原文有）
- [ ] 没有在正文里写译者注、译按

### 限定词专项

单独过一遍这类词，它们在政经文献里决定论证成立与否：

- [ ] `tends to` / `tendentially` → 趋势，非必然
- [ ] `in the long run` → 长期，非最终
- [ ] `only` / `merely` → 没被吞掉
- [ ] `not necessarily` → 未必，非不会
- [ ] `may` / `can` → 可能 / 能够，没混
- [ ] `presupposes` → 以…为前提，非意味着
- [ ] `determines` / `conditions` → 决定 / 制约，没混
- [ ] `as such` → 就其本身而言，非因此
- [ ] `not all` → 并非所有，非所有都不
- [ ] `few` → 很少，非一些

## 哪些判断不能替你做完

有些决定是译者的职责，有些是作者的。前者不要推给用户，后者不要替用户做。

**自己定的**（不必上报）：语句怎么断、语序怎么调、虚词加哪个、被动改主动、用什么量词。这些问题问用户等于把工作推回去。

**必须上报的**，只有四类：

| 类型 | 判定标准 | 上报时给什么 |
|---|---|---|
| 语义歧义 | 原文两种读法都成立，且译法不同会导致结论不同 | 两种译法、各自后果、你的选择与理由 |
| 术语未定 | 项目表和总表都没有，或表里并存两种 | 候选译法、依据（谁这么用过）、建议 |
| 学派立场 | 选词本身表示站队（`surplus approach` 剩余方法／剩余进路） | 各立场的通行用法，让用户选 |
| 原文疑误 | 指代不明、公式符号前后矛盾、数字对不上、疑似笔误 | 位置、矛盾在哪、**不要替作者改** |

四类的共同点：**换一种处理方式，读者理解到的内容会变**。文风、节奏、句子切分不属于此类。

**不要用"请确认"打发。** 说"这个词我译为 X，因为 A 处这样用；若改译为 Y 则会被读成 B"——把后果说清楚，用户才能在十秒内做决定。列一堆没有判断的疑点，等于把校对工作原样退回。

**清单为空也要说清楚空的是哪一层。** "没有需要你决定的地方"只对语义层成立，机械层由 `fidelity_check.py` 负责，两层不要混着说。

生成这份清单：`python scripts/review_queue.py 原文.md 译文.md --glossary _work/x_术语.csv --manual _work/x_人工待校.csv`。人工待校 CSV 在翻译过程中随手记，不要等译完再回忆——那时的记忆已经被后面的段落覆盖了。

## 报告要写什么

交付时附一份简短报告，包含四部分：

1. **校验结论**：`fidelity_check.py` 的输出，直接贴。
2. **原文疑点**：疑似错误、内部矛盾、缺页、公式与正文不符。写清位置和自己的判断，**不替作者圆场，也不擅自改**。
3. **提取缺陷**：哪些地方是提取工具造成的、怎么处理的（改了哪几处）。
4. **没做的部分**：附录缺失、公式是图片无法提取、参考文献表未纳入等。

报告里不要出现 token、本机路径以外的敏感信息。

---

## 不该做的

- 不要在译文末尾加"译者说明""术语对照表""译后记"——除非用户明确要求。它们破坏结构对应。
- 不要为了让 `fidelity_check.py` 通过而改译文结构。脚本报的块级不一致，九成是真的漏了或多了。
- 不要在报告里说"已仔细校对，确保准确"这类空话。列出查了什么、查出什么，比保证有用。
- 不要把"通读一遍"当成已做。做没做，报告里看得出来。
