# 图与表：Markdown 装不下的部分怎么补

Markdown 的图像语法 `![]()` 是行内元素：没有宽度、没有图注、没有面板。而论文里的一张图是个复合对象——图像、图注、子图说明、正文里"如图 3 所示"的引用，四样绑在一起才算一个"图"。

抽取器按阅读顺序输出文本，这四样就散开了。于是译文里最常见的三种坏相：

| 坏相 | 表现 | 读者的感受 |
|---|---|---|
| **拆散** | 四面板图变成四张图，各占一行、各自满宽，竖着摞下来 | 比例全错，面板顺序靠猜，图注掉到中间 |
| **游离** | 图注跑到图片上方，或隔了三段才出现 | 不知道这段文字在说哪张图 |
| **裸图** | 图片后面没有图注，正文里的"图 3"指向空气 | 图号引用失效 |

还有第四种，不是结构问题而是可读性：**宽图被压小**。一张 12 面板的实验对比图塞进正文宽度，图里的刻度与图例小到看不清。

先明确两条原则，它们管的是两件不同的事：

- **内部版式**：**图是证据，不是装饰。** 图的版式不是译者的自由裁量范围——把并排的面板改成竖排、把两个独立图合到一个块里、裁掉半边，都会让读者看到的证据与原文不同。这部分只做一件事：**把被抽取器打散的原文版式恢复回去**，不做创意排版。
- **所在位置**：PDF 为分页与双栏把浮动对象放到离引用段落很远的地方，这是排版约束、不是作者的意思。Markdown 没有页、没有栏、没有浮动体，所以**图与表要移到正文首次引用它们的段落之后**（见 §2）。搬位置不算重排，改内部版式才算。

---

## 1 三条底线

做完这四条，图就不会"乱"：

1. **一个逻辑图 = 一个图块 + 一段紧跟其后的图注。** 不要把一个图注拆成两段，也不要把两张独立图塞进一个图注下面。
2. **图注紧跟图，中间不插正文。** 图注段落与图片之间最多一个空行。
3. **图号与正文引用必须对得上。** 译文里每个"图 N"都能找到图注，每个图注都至少被正文引用一次（综述性引用不算）。
4. **图块紧跟首次引用它的段落。** PDF 的浮动位置不是内容；Markdown 里读者读完"如图 3 所示"低头就该看到图 3（做法见 §2）。

判断"一个逻辑图"还是"N 个独立图"，看**原文图注**：一条图注里带 `(a) (b) (c)` 的，是一个逻辑图（哪怕被抽成了四张图）；四条独立图注（`Figure 2`、`Figure 3`）的，是四个图，不许合并。

## 2 浮动对象就近重定位

**为什么必须做**：PDF 里的一张图常被放到下一页的页顶，正文里"如图 3 所示"却在上一页末尾；双栏论文里图还可能浮到另一栏。抽取器按阅读顺序输出，这个距离被原样带进 Markdown，读者要来回翻才能把图和论述配上。Markdown 是线性文档，没有理由保留这个约束。

**规则**：把每个浮动对象整体移到**正文中第一次引用它的段落之后**。

| 情形 | 处理 |
|---|---|
| 正文有「图 N」／「Figure N」首次引用 | 图块（含图注、子图说明）移到该段之后 |
| 一张图被多处引用 | 以**首次**为准，后续引用不动 |
| 「表 N」／「Table N」 | 表格连同表注一起搬 |
| 完全没被引用的图（封面图、附录图、无编号图） | 保持原相对位置，在交付报告里列为"未就近对象"，不猜 |
| 原本就紧挨引用段（≤ 3 行） | 不动，脚本判为"原本就近" |

**只搬位置**：图片路径、`alt`、`width`、面板并排关系、图注文字与编号、表格行列与数值、表注、正文段落内容与顺序，一个都不改。搬完图号、交叉引用、公式编号都不变，正文引用不用改。

用脚本执行，不要手工拖拽——手工搬最容易把图注、表注落在原地：

```bash
python scripts/figures.py relocate 译文_zh.md                          # 先看计划，不改文件
python scripts/figures.py relocate 译文_zh.md --apply --csv _work/图表重定位.csv
python scripts/figures.py audit 原文.md 译文_zh.md --csv _work/图目录.csv
python scripts/fidelity_check.py 原文.md 译文_zh.md \
    --glossary _work/x_术语.csv --float-reflow --strict
```

脚本给搬过的块加一对标记，用于幂等、就近性审计与结构对账：

```markdown
<!-- float:moved fig=3 anchor=L214 -->
<!-- figure:start -->…<!-- figure:end -->

**图 3**　……（图注照译，紧跟图块，仍在块外）
<!-- float:end -->
```

`--float-reflow` 的含义要说清楚：它**只**让浮动对象在块序列里的位置不参与一一对应，改为按多重集合核对图片路径、图注编号与表格行数；**正文段落仍逐块比对**，删段、并段照样报硬性失败。不加这个参数时，搬动过的表行会触发"块级结构不一致"，脚本会提示补参数。

CSV 清单逐块记录 `类型,编号,原行号,锚段落行,动作,说明`。交付前对着它数一遍：搬了几块、有没有"无正文引用"的块、有没有块被判"原本就近"。

## 3 并排图块：唯一能把面板放回并排的写法

Markdown 本身做不到，但 Markdown 允许内联 HTML，用一张无边框表格承载面板是最稳的做法：

```markdown
<!-- figure:start -->
<table>
<tr>
  <td><img src="images/fig2a.png" alt="图 2(a) 输入模块" width="48%"></td>
  <td><img src="images/fig2b.png" alt="图 2(b) 编码器" width="48%"></td>
</tr>
<tr>
  <td><img src="images/fig2c.png" alt="图 2(c) 解码器" width="48%"></td>
  <td><img src="images/fig2d.png" alt="图 2(d) 输出模块" width="48%"></td>
</tr>
</table>
<!-- figure:end -->

**图 2**　所提框架总览。(a) 输入模块；(b) 编码器；(c) 解码器；(d) 输出模块。
```

几个技术要点，都是踩过的坑：

- **用 `<table>` 而不是 `<div style="display:flex">`。** GitHub 会剥掉 `style` 属性，flex/grid 全部失效，图又变回竖排；`table` + `width` 属性在各家渲染器（Typora、VS Code、GitHub、pandoc）都保得住。
- **宽度用 `width="48%"` 而不是 `style="width:48%"`**，理由同上。两个面板用 48%，三个 32%，四个 24%。
- **图注留在块外面，仍然是普通段落。** 不要塞进 `<figcaption>`：块内的东西对账脚本会折叠成一个整体，图注放在外面才能逐段对齐，也让纯文本渲染下仍然读得到。
- **`<!-- figure:start -->` / `<!-- figure:end -->` 不能省。** `fidelity_check.py` 靠它把整块折成一"处"，否则一张四面板图会被算成"多出四张图 + 多个 HTML 段落"，结构对账全红。`figures.py` 也靠它识别已处理过的块。
- **alt 要写**，格式"图 N(子图号) 一句描述"。转 docx、做检索、图挂了之后的占位都靠它。空 alt 会被 `figures.py audit` 点名。
- **源文与译文都整理成并排图块时**，`fidelity_check.py` 会把两侧都折叠成「一个逻辑图」再对账（早期版本只折叠译文，会误报「源 2 处、译 1 个块，数量不一致」）。`figures.py audit` 也会单独查块内 `<img>` 的文件路径与 alt，避免块内断图查不出来。
- `relocate` 找首次引用时会跳过 YAML front matter：元信息里出现 `Figure 1` 不算正文引用，否则图会被搬到文件开头。

用 `figures.py group` 可以自动生成这个块：

```bash
python scripts/figures.py group 译文_zh.md            # 只报告，看它打算合哪几组
python scripts/figures.py group 译文_zh.md --apply    # 确认后写回
```

它只合并"连续、中间没有文字的裸图"，有图注隔开的两张图不会被误合。

## 4 子图说明

子图说明有两种存在形式，处理方式不同：

- **原文是文字**（`Figure 2: (a) Input. (b) Encoder.`）——照译，保持 `(a) (b) (c)` 的结构。段内用分号隔开，或每条一行；**不要合并成一段散文**，读者要靠 (a)(b) 对照图看。
- **说明烧在位图里**（图里自带 "Input / Encoder" 字样）——**不补写**。补写就是"增"，而且你无法确认位图里的文字是否与正文一致。在交付报告里提一句"图 2 的子图标注为位图，未转文字"即可。

子图数量多（超过 6 条）时，图注下面用无序列表，每条一个面板：

```markdown
**图 5**　消融实验结果。

- (a) 去掉正则化；
- (b) 去掉数据增强；
- (c) 去掉残差连接；
```

## 5 宽图与密集图

正文宽度是固定的，**不要在 Markdown 里靠 `width="200%"` 放大**——多数渲染器会裁切或溢出。

- **提取时提高分辨率**：先看抽出来的图本身有多少像素——宽度不足约 1200px 的，缩到正文宽度就会糊。这时回 PDF 按图所在区域重裁一张 300dpi 的：

  ```bash
  # 第 7 页、左上角起 120,340，裁 900×420 像素的区域，输出 300dpi
  pdftoppm -r 300 -png -f 7 -l 7 -x 120 -y 340 -W 900 -H 420 paper.pdf fig2
  ```

  比在 Markdown 里靠 `width` 放大靠谱得多——放大位图只会更糊。
- **确实读不清时，优先换提取质量，而不是拆图**。拆成"总图 + 逐面板放大"改变了原文结构，属于重排，不做。
- **带数字的热力图/矩阵图**：如果原文另附了数值（附录表格、开源仓库），可以重建为 Markdown 表并注明来源；拿不到数值就不要动图。
- 在交付说明里注明"图 N 为位图，图内文字不可检索"，读者就知道该回原文看。

## 6 实验表格：比图更容易塌

表格不是图，但抽取器一样会弄坏，而且坏得更彻底——数字错位比图糊更危险。

- **简单表**：Markdown 表格，数字列右对齐（`---:`），单位写在表头。
- **多级表头、合并单元格**：Markdown 表格不支持 `colspan`/`rowspan`，用 HTML 表格：

```markdown
<table>
<tr><th rowspan="2">模型</th><th colspan="2">准确率（%）</th></tr>
<tr><th>Top-1</th><th>Top-5</th></tr>
<tr><td>ResNet-50</td><td>76.1</td><td>92.9</td></tr>
</table>
```

- **跨页被拆成两个表**：合并回一个，表头只留一份，中间不要插"（续）"。
- **表注单独成段**，紧跟在表格下面，不要塞进最后一个单元格。
- 表格里的 `±`、星号、括号中的标准误，一个字符都不动（见 `accuracy-rules.md` 第 3 节）。

## 7 最终交付：Markdown 是工作稿，不是阅读版

这一点要说清楚，否则会一直在 Markdown 里跟排版较劲。

**Markdown 的价值是可 diff、可对账、可版本控制**，不是精排。图的精细版式（并排、图注居中）本来就不该由它承担。但"图放在引用段落旁边"属于**阅读顺序**，不是精细排版，必须在 Markdown 里就做对（§2）。所以：

- **工作稿**：`<stem>_zh.md`，按本文规范处理图块，够读、够对账。
- **阅读版**：需要精排时导出 HTML 或 docx。

```bash
# 导出单文件 HTML（图块按表格并排，宽图自适应）
pandoc <stem>_zh.md -s --embed-resources --css fig.css -o <stem>_zh.html

# 导出 docx（表格布局会保留，图按宽度缩放）
pandoc <stem>_zh.md -o <stem>_zh.docx
```

一份够用的最小 CSS：

```css
img { max-width: 100%; height: auto; }
table { border-collapse: collapse; margin: 1em auto; }
td { border: none; padding: 4px; text-align: center; }
figure, table + p { text-align: center; }
```

要 docx 且要求期刊格式时，走 `workbuddy-docx`，别在 Markdown 里堆 `<br>` 和空行——那会破坏结构对账。

## 8 交付前逐条过

- [ ] 每个图／表块都紧跟在**正文首次引用它的段落之后**（`figures.py relocate` 已跑、`_work/图表重定位.csv` 已核），无引用的块已写进交付报告
- [ ] 搬动过的块带 `<!-- float:moved … -->` / `<!-- float:end -->` 标记，图注／表注跟着块一起搬了，没有落在原地
- [ ] 每条图注都紧跟在自己的图块后面，中间没有正文段落
- [ ] 一张图注对应一个图块（没有两个图注共用一个块，也没有一个图注对应四个散块）
- [ ] 多面板图要么是整张图，要么是一个并排图块，没有竖排摞在一起
- [ ] 并排图块有 `figure:start/end` 标记，块内 `img` 有 `alt` 与 `width`
- [ ] 译文里每个"图 N"都能找到图注；每个图注都被正文引用过
- [ ] 图号连续，没有因合并/删除而跳号
- [ ] 图片路径都存在（相对译文所在目录）
- [ ] 多级表头用 HTML 表格，数字列右对齐，表注在表下方
- [ ] 交付说明里写清了哪些图是位图、哪些子图标注未转文字
