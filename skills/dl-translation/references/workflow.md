# 长文、断点与批量

`SKILL.md` 的主流程适用于一篇、一次能读完的论文。下面三种情形需要额外的做法。

---

## 1 长文（正文超过约 1.5 万词）

单次输出越长，后半段越容易滑向"概述"——句子变短、条件被省、公式退化成"上式"。所以分块是质量措施，不是效率措施。

### 分块

- 以 `##` 二级标题为界；附录按 `A`、`B` 各成一块；证明特别长的，一个 `Proof` 也可以单独成块。
- 单块超过约 3000 字（中文）再按段落切，切口选在段落边界，不要切断一个 `$$` 块、一个 `align` 环境或一个 `cases`。
- 每块开工前把**上一块末尾三段**一起读，保证代词、术语、符号不断裂。

### 断点续译

```bash
_work/
  <stem>_原文.md          # 提取稿
  <stem>_术语.csv         # 已定术语（跨块共用，不要每块重建）
  <stem>_符号候选.csv     # 符号抽取结果
  <stem>_进度.md          # 已完成块清单：块号、标题、行范围、校验状态
  <stem>_zh.part1.md      # 分块产物
  <stem>_zh.part2.md
```

每完成一块，立刻在 `_work/<stem>_进度.md` 记一行：`## 3 方法 | L120–L340 | 已译 | 公式 12 处已对`. 中断后从最后一行的下一块开始，不要凭记忆判断译到哪了。

分块产物最后按顺序拼接成 `<stem>_zh.md`，再统一跑校验。拼接时注意块之间的空行——两个 `##` 标题之间必须有且只有一个空行，否则结构对账会把它们算成一块。**浮动对象的就近重定位在拼接完成后一次性跑 `figures.py relocate`**：分块时搬图会让锚段落落在另一块里，进度记录也对不上。

### 逐块校验

不要等全文译完再校验。每块译完立刻：

```bash
python scripts/math_fidelity.py 原文.md <stem>_zh.partN.md   # 公式
python scripts/notation.py extract 原文.md -o _work/符号候选.csv  # 全文只需一次
```

公式错误在第 3 块发现，改一处；等到第 12 块才发现，要回溯改十几处。

---

## 2 原文更新了怎么办

论文有 v2、预印本转正刊、作者修了笔误——三种情况处理不同：

| 情形 | 做法 |
|---|---|
| 只改了措辞、公式未动 | 重跑 `math_fidelity.py` 确认公式未变，再按段落对齐人工过一遍改动处 |
| 公式或定理变了 | 不能增量改。以新版为源重译受影响的节，旧译文对应节作废；在 front matter 的 `source_sha256` 更新 |
| 换了 PDF 版本但内容等价 | 重新提取，比对提取稿的块数与公式数，一致则沿用旧译文 |

`paper_meta.py` 记录的 `source_sha256` 就是用来判断"这次是不是同一份原文"的。

## 3 批量（一次多篇）

同一批论文（同一作者、同一主题、同一会议）连着译时，术语会跨篇漂移。做法：

1. 先抽全部原文的候选术语，合并去重，人工定一遍**批次术语表**；
2. 每篇仍建自己的项目表，但从批次表继承已定的条目；
3. 每篇译完后，把新定的条目（`status=已定`）回填批次表，下一篇即可查到。

```bash
# 批量抽候选
for f in *.md; do
  python scripts/extract_terms.py "$f" -o _work/ --glossary references/glossary --min-count 3
done
```

批次结束后核对一遍：同一个英文词在不同篇里是否有两种译法。有，就是该收敛的时候——不要继续逐篇临时决定。

---

## 4 只译一部分

用户只要摘要、引言、某一节、或只要定理与证明时：

- 仍然先做第 2 步（术语与符号），只是范围缩小到该节；
- **符号一览照建**，但"出现范围"列写"（本次译文范围）"，并在表下注明节选范围与原文完整版的关系；
- 校验只对节选部分做，`fidelity_check.py` 会报"块数不一致"——用 `--allow-block-drift` 跳过结构项，其余项（引用、公式、术语、`keep` 术语反向检查）仍然有效；若节选里含图表，还要带 `--float-reflow`；
- 交付时明确说明节选了哪几节，不要让读者以为拿到的是全文。

---

## 5 与其他工具的边界

- **PDF 提取**：`scripts/mineru_extract.py`，细节见 `references/mineru.md`。公式被拆成图片、表格塌成纯文本时，宁可换 `--model vlm` 重跑，也不要在残缺的提取稿上翻译。
- **Word/PDF 交付**：本流程产出 Markdown。要 docx 用宿主的 docx 转换（或 pandoc）；**要 PDF 走 `scripts/md2tex.py`**（译文 Markdown → XeLaTeX → PDF，版式贴着原文：编号右对齐、多行公式等号对齐、引文与符号表可跳、书签可用），细则见 `references/pdf-latex.md`。**不要在 Markdown 里为了排版加空行、加 `<br>`**——那会破坏结构对账。
- **纯 LaTeX 源码级的重建与编译校验**不在本 skill 范围内：这里译的是内容，不是排版工程。`md2tex.py` 只从**已定稿的中文 Markdown** 生成排版件，不回改原文结构。
