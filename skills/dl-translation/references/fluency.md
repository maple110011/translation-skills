# 流畅化改写：保真项不动，句法归中文

这份文件回答一个问题：**译文准确、校验全绿、但读起来是英文的倒影，怎么办。**

旧口径是"允许翻译腔"。那条口径解决了一个真问题（怕改写改坏公式与条件），代价是把"语序照英文、长句不拆、名词化保留"写成了许可——于是每一句都合格，整篇读不动。现在改成：

> **保真项一个不动，句法一律归中文。** 不追"雅"，但不容忍"读着像译文"。

两者不矛盾，因为可改的东西和不可改的东西不在同一个层面上。

## 一、分界线：什么能动，什么不能动

| 类别 | 例子 | 能否改 |
|---|---|---|
| 公式、符号、编号、`\tag`、`\label` | `$\mathcal{O}(n)$`、`(3)` | **不动**。一个字符都不动 |
| 术语（`kind=term` / `kind=keep`） | 相合性、prior-data fitted networks | **不动**。要换回项目表换，整篇一起换 |
| 引用与文献 | `(Smith et al., 2020)`、`[12]`、`\cite{}` | **不动** |
| 代码与伪代码 | 缩进、行序、语言标记 | **不动** |
| 量词、情态、概率模式、否定辖域 | `for any`、`there exists`、`a.s.`、`not all` | **不动**（这是准确性的肉身） |
| 定理环境的标签 | Theorem / Proposition / Lemma | **不动** |
| 数字、单位、区间开闭 | `$10^{-3}$`、`\le` | **不动** |
| 语序、断句、主从、虚词 | 下面第三节 | **可改，且应当改** |
| 名词化、被动、代词密度 | 下面第三节 | **可改** |
| 段落切分、句序跨段 | — | **不可改**（对账基准） |

判断只有一句：**改完之后，一个只会中文的读者拿去复现代码、核对证明，会不会与读英文原文得到不同的结论？** 会，就是改坏了；不会，就是该改的。

## 二、四种最容易"改着改着改出意思"的地方

这四类是数学文本特有的雷，看起来只是把话说顺，实际动了命题。

**1. 量词的顺序。** `for any $\epsilon>0$ there exists $n_0$` 是"对任意 $\epsilon>0$，存在 $n_0$"，不是"存在 $n_0$，对任意 $\epsilon$"。中文为了顺口把"存在"提前，两个量词的依赖方向就反了，一致性变成非一致性。

**2. `if` / `only if` / `iff` 的辖域。** 拆句时把 `if` 从句挪到后半句、或把"当且仅当"改写成"若…则…"，条件与结论的对应关系就换了。拆句只许在**主句与从句之间已经用逗号分开**的位置拆，不许把从句搬到另一个分句后面。

**3. 定义句与陈述句。** "称 $X$ 为……，若……"是定义，"$X$ 是……"是断言。为了顺口把定义改写成陈述，读者会以为作者在主张一个事实。`we say` / `is called` / `is defined as` / `denote` 这几种句式，改写时保持句式类型不变。

**4. 程度的软化。** `at most` 不是"不超过"以外的任何说法；`with probability at least $1-\delta$` 不是"大概率"；`up to a constant` 不是"近似地"；`it is easy to see` 不是"显然"（"显然"在中文数学写作里是一个更强的断言，等于宣称无需证明）。**流畅化不许碰这类词的强度**——它们读起来不顺，是因为它们本来就是精确的。

另外两条通用雷：**因果连词不能凭空加**（原文只是先后，中文不能写"因此"）；**否定范围不能挪**（`not all` 改写成"所有…都不"是整段反了）。

## 三、可以动手的十种手术

按收益排序。**前五种解决大部分"读着像译文"的问题**，后五种看情况。

**1. 拆句。** 英文一句话套三个从句，中文读到句末已经忘了主语。在从句边界拆成两到三句，主语按需补出（补的是汉语必需的指代，不是新信息）。

> ✗ 作者提出的这一在样本量趋于无穷时仍保持相合性的估计量，其计算复杂度依赖于维数。
> ✓ 作者提出了一个估计量，它在样本量趋于无穷时仍保持相合性。该估计量的计算复杂度依赖于维数。

注意拆句时**不要顺手加"但""因此""实际上"**：拆开的两句在原文里是并列，就不许在中文里变成转折或因果。上面第二句用"该估计量的"重复主语，而不是"其"——代词还原，信息量不变。

**2. 长定语改成谓语或从句。** 中文不擅长"的"字链，擅长短句递进。

> ✗ 对具有有界方差的随机变量的期望的估计
> ✓ 估计有界方差随机变量的期望

**3. 名词化 → 动词。**

> ✗ 对参数进行了估计并对误差进行了分析
> ✓ 估计了参数，并分析了误差

**4. 被动 → 主动（施事明确时）。** 原文施事有意模糊（`it is assumed that`）的**不要**改，那是作者的写法。

> ✗ 该界被定理 2.1 所给出。
> ✓ 定理 2.1 给出了该界。

**5. 代词还原。** 英文一段里五六个 `it` `this` `they` 都指得清，中文照译会指代不清。在可能歧义处换成具体名词；同段代词出现三次以上就考虑还原。

**6. 虚动词删掉。** "进行／加以／予以／作出／对……而言"绝大多数是英文名词化的残留：`perform an analysis` 是"分析"，不是"进行分析"。

**7. 状语前移。** 英文可以把"在……条件下""就……而言"一路后缀，中文读到第三个介词短语就断了。提到句首，或另起一句。

> ✗ 该结论在假设 A 成立且样本独立同分布的条件下对任意紧集 $K$ 成立。
> ✓ 在假设 A 成立、样本独立同分布的条件下，该结论对任意紧集 $K$ 成立。

**8. 插入语归位。** `however`、`in particular`、`note that`、`surprisingly` 嵌在句中会把主干截断。前置，或另起短句。

> ✗ 该方法，值得注意的是，在低数据情形下反而更稳。
> ✓ 值得注意的是，该方法在低数据情形下反而更稳。

**9. 并列项对齐。** `A, B, and C` 若一项两字、一项十字，读起来是散的。让三项词性一致、结构一致；原文本来就不齐的，照实译，不要为了齐整把从句压成一个词（那是增删）。

**10. `there is` / 存在句重铸。** `There exists a constant $C$ such that…` → "存在常数 $C$，使得……"，不要"有一个常数 $C$ 存在，使得……"。

## 四、怎么执行：改在哪一步、改完怎么验

**位置很关键：放在机械校验之后、审校清单之前。** 先让公式、结构、术语的门禁过关，再做改写；改完**重跑一遍门禁**。反过来（先改写再校验）会把改写引入的公式破坏混进校验结果里，分不清是翻译错还是改写错。

```
第 3 步 翻译 → 第 4 步 机械校验（门禁 A）→ 流畅化改写 → 重跑第 4 步（门禁 B）→ 第 5 步 审校
```

三条执行约束：

1. **只在句内改。** 不跨段、不合并两段、不拆一段、不把一句挪到邻段。段界是 `fidelity_check.py` 的基准。
2. **一条一处。** 一次只处理一个病灶，不要"既然改了这句就顺手把整段重写"。整段重写的 diff 无法复核，而且最容易带进未察觉的语义变化。
3. **保不住就退回。** 某句改了两版都拿不准是否等价，保留原译。**改不动的代价是生硬，改错的代价是不准**——这两者不等价。

**分块改，每块动手前读前后文。** 只读当前块会把衔接改断：上一块改成短句、这一块还是长句，全文像两个人写的。每块开始前读**已改写的**上一块末尾三段，以及下一块开头一段。

**第一块改完，定一个"中文基准"。** 挑两三句定稿的改写贴进 `_work/<stem>_流畅基准.md`，后面每块比照它——一句多长、连接词用不用、术语密集的句子怎么断。"通顺、克制、学术"这类形容词对模型没有约束力，三句实物有。这份基准与项目术语表并列：术语表管词，它管句。

改完必须重跑：

```bash
python scripts/normalize_math.py <stem>_zh.md --inplace
python scripts/math_fidelity.py <stem>_原文.md <stem>_zh.md --csv _work/公式差异.csv --strict
python scripts/fidelity_check.py <stem>_原文.md <stem>_zh.md \
    --glossary _work/<stem>_术语.csv --float-reflow --strict
```

三条各拦一类改写事故：`math_fidelity` 拦公式被顺手"整理"；`fidelity_check` 拦段落被合并、`keep` 术语被译成中文、引用被改动；`normalize_math` 保证新写的公式定界符没走形。**门禁 B 与门禁 A 结论不一致时，先怀疑改写，不要先怀疑脚本。**

## 五、验收：什么叫"通顺了"

不设"文采"标准，只设**读者成本**标准。逐条可判：

- [ ] 遮住英文读一遍，**不需要回看原文**就能懂每一句在说什么
- [ ] 一句话里"的"不超过三个；一段里不超过六个
- [ ] 没有连续两句用"被"；没有被……所……
- [ ] 没有"进行／加以／予以／作出 + 名词"的滥用
- [ ] 单句超过 80 字且中间无标点的，都检查过是否该拆
- [ ] 一句里只有一个主谓核心；两个核心的已拆开
- [ ] 同段内代词不超过三个，且每个都指得清
- [ ] 连续三句不以同一个词开头（数学陈述里主语是符号的除外）
- [ ] 没有"值得注意的是""综上所述""不难发现"这类原文没有的填充语
- [ ] 定理、定义、假设的**句式类型**没变（定义还是定义，断言还是断言）
- [ ] 量词顺序、`if/only if` 辖域、概率模式、程度词，逐条核过

**通顺不等于短。** 有些句子必须长，因为条件多、限定密。该长的地方长，该断的地方断，判据是"读者在哪里卡住"，不是"句子多少字"。

## 六、不要做的事

- **不要为了顺口补逻辑。** 原文并列，不能写成"因此"；原文递进，不能写成"换句话说"。
- **不要为了顺口删限定。** `under mild assumptions`、`in the finite-sample regime`、`for sufficiently large $n$` 读起来累赘，但它们是结论的适用范围。
- **不要把"作者没说的"补成通顺。** 英文省掉的主语，中文常常要补——补的必须是从上文能唯一确定的那个，不能是新引入的施事。
- **不要统一"看起来重复"的表述。** 作者在同一段里换用两个说法，多半是有意的（一个指定义、一个指性质）。
- **不要把 `keep` 术语改成中文。** 那是第 2 步的裁定，不是第 4.5 步的措辞问题。要改回项目表改，整篇一起改。
- **不要一次改全篇。** 分块改、每块改完跑门禁。全篇一次性改写，出错时无法定位是哪一块引入的。
