# 符号一览表

数学、统计、深度学习论文里，符号密度远超自然语言文本。读者读到第 5 页回过头找 $C$ 是什么、$\mathcal{D}$ 是不是训练集时，一张开头的表省下的时间比全文任何润色都多。所以这张表是**交付物的一部分**，不是可选的装饰。

---

## 1 位置与标记

- **位置**：YAML front matter 之后、正文第一节之前。读者一打开就看见。
- **标记**：用 HTML 注释把整块包起来。所有对账脚本靠这两个标记把表从正文里剥出去——表是这次翻译**新增**的东西，原文里没有，不剥掉会让结构对账报"多了一个标题和 N 行表格"。

```markdown
<!-- notation:start -->
## 符号一览

| 符号 | 含义 | 出现范围 |
|---|---|---|
| $n$ | 样本量 | 全文 |
| $d$ | 特征维数 | 全文 |
| $x_i \in \mathbb{R}^d$ | 第 $i$ 个样本的特征向量 | 第 2 节起 |
| $y_i \in \{0,1\}$ | 第 $i$ 个样本的标签 | 第 2 节起 |
| $f_\theta$ | 由参数 $\theta$ 参数化的预测函数 | 第 2 节起 |
| $\hat{f}$ | 由训练集得到的估计 | 第 3 节起 |
| $\mathcal{D}_n$ | 训练集，含 $n$ 个样本 | 全文 |
| $\mathcal{R}(f)$ | 风险，$\mathbb{E}[\ell(f(X),Y)]$ | 全文 |
| $\hat{\mathcal{R}}_n(f)$ | 经验风险，在 $\mathcal{D}_n$ 上平均 | 全文 |
| $\ell(\cdot,\cdot)$ | 损失函数 | 第 2 节 |
| $\sigma$ | 噪声标准差 | 假设 2 |
| $C, c$ | 通用常数，同一式内可能出现多次 | 全文 |
| $\|\cdot\|_2$ | 欧氏范数；矩阵情形为谱范数，另行注明 | 全文 |
| $\mathcal{O}(\cdot)$ | 渐近上界记号，常数与 $n$ 无关 | 全文 |
| $O_p(\cdot)$ | 依概率有界的随机量记号 | 第 4 节起 |
| $a \wedge b$ | $\min\{a,b\}$ | 附录 A |
<!-- notation:end -->
```

三点硬要求：

1. **每格符号用 `$…$` 包住**，否则渲染成纯文本，上下标会掉。`notation.py check` 会把没包 `$` 的格子标出来。
2. **符号串与正文逐字符一致**：`\hat{f}` 不能写成 `f̂`，`\mathbb{E}` 不能写成 `E`，`\|\cdot\|_2` 不能写成 `||·||₂`。手抄是这张表最大的错误来源。
3. **表格里的竖线要转义**。范数 `\|x\|` 在 Markdown 表格里会被当成列分隔符。两种写法都可用：`\|x\|`（转义）或 `\Vert x \Vert`（更稳，不依赖渲染器对 `\|` 的处理）。**不要**直接写 `|x|`——那是绝对值，含义也变了。

## 2 收什么，不收什么

**表的价值取决于它有多短。** 读者读到第 8 页遇到不认识的 $\mathcal{P}$，只有在他相信"这表值得扫一眼"时才会回去查；表长到三十行、一半是 $\mathbb{R}$ 和 $\mathbb{E}$，他就不查了，表等于没有。

收：

| 类别 | 例子 |
|---|---|
| 数据记号 | $n$、$d$、$N$、$T$、$x_i$、$y_i$、$\mathcal{D}_n$ |
| 参数与超参数 | $\theta$、$W$、$b$、$\lambda$、$\eta$、$K$（层数、簇数等） |
| 函数与映射 | $f_\theta$、$g$、$\phi$、$\pi$、$\ell$、$\mathcal{L}$ |
| 作者自定义的集合与空间 | $\mathcal{X}$、$\mathcal{Y}$、$\mathcal{P}$、$\mathcal{F}$（函数类）、$\Theta$ |
| 范数与内积 | $\|\cdot\|_2$、$\|\cdot\|_F$、$\langle\cdot,\cdot\rangle$ |
| 渐近记号 | $\mathcal{O}$、$o$、$\Omega$、$\Theta$、$\tilde{\mathcal{O}}$、$O_p$、$o_p$ |
| 概率模式 | a.s.、a.e.、$\Rightarrow$（依分布）等，若作者自定义 |
| 假设与条件的标签 | A1–A4、H1、C1，若正文按标签引用 |
| 常数与界 | $C$、$c$、$\varepsilon$、$\delta$——**只在多处复用、或彼此有区分时**（$C$ 与 $C_1$ 不是一回事，才要列） |

不收：

- **通用记号**：数集 $\mathbb{R},\mathbb{N},\mathbb{Z},\mathbb{Q},\mathbb{C}$（连同 $\mathbb{R}^d$）、期望与概率算子 $\mathbb{E},\mathbb{P},\mathrm{Var},\mathrm{Cov}$、$\nabla$、$\partial$、$\infty$、$\emptyset$，以及纯索引 $i,j,k$。它们在每一篇里都是同一个意思，列出来只占版面。
  - **例外：带上下标的算子要收。** $\mathbb{E}_{\Pi}$ 不是"期望"，是"对先验取期望"；$\nabla_\theta$ 是"对参数求梯度"。上下标才是信息。
  - 希腊字母一律不收豁免：$\pi$ 在贝叶斯论文里是后验预测分布，在强化学习里是策略，在几何里是圆周率。看似眼熟，恰恰最容易认错。
- **拉丁大写单字母**也不自动豁免：$C$ 可能是通用常数，也可能是一个集合、一个类、一个代价函数。
- 一次性出现的临时记号（推导中间引入、随后不再用）；
- 纯排版符号与函数名（$\log$、$\exp$、$\max$、$\int$、$\sum$）；
- 原文没有、你为了讲清楚而加的东西（那属于"增"，见 `accuracy-rules.md` 第 7 节）。

**篇幅**：一篇论文 12–20 行是常态。超过 25 行先怀疑自己收宽了，再看是不是真的符号多。**同一对象的几种写法合成一行**（`$\boldsymbol{X}$、$\pmb{X}$、$X$` 一行说完），不要一个写法一行。

**这些规则脚本能代劳一半**：`notation.py extract` 默认就把常见符号滤掉，并在输出里报"已略去 N 个"；已经写宽的表用 `notation.py prune` 删掉只含通用记号的行（默认只演习，`--apply` 才写回）。

判断标准只有一条：**读者读到半路，会不会想回头查它**。会，就收。

## 3 排序与写法

- **按首次出现顺序排**，不按字母序。读者是顺着读的，字母序只在"查字典"时有用，而这里的需求是"追上下文"。
- **同一符号多义时分行**，并在"出现范围"列写清适用区间。宁可两行重复，也不要合并成一句含混的话：

| 符号 | 含义 | 出现范围 |
|---|---|---|
| $T$ | 迭代总步数 | 第 3 节 |
| $T$ | 转置 | 附录 B |

- **"含义"列用中文**，术语与项目术语表一致；专名保留拉丁字母（`$\mathcal{D}$：ImageNet 训练集`）。
- **定义式可以写进含义列**，但要短：`$\hat{\mathcal{R}}_n(f)$：经验风险，$\frac{1}{n}\sum_i \ell(f(x_i),y_i)$`。长定义放正文，表里只给一句话。
- **索引类可合并**：`$i,j$：样本索引｜$k$：类别索引｜$t$：迭代步`。合成一行比列十几行可读。
- **"出现范围"列可以用"全文"**，不要空着——空着读者不知道这是全文通用还是某节专用。

## 4 与原文 Notation 节的关系

原文若已有独立的 Notation / 符号说明节：

1. **原位照译，不删不挪**。那是原文的结构，删了就对不上账，也改变了作者的叙述顺序。
2. **开头仍建"符号一览"**，但它是补全版：把原文该节没列、而全文反复使用的符号补进去。表里可以加一句说明："依原文 §2 记号约定整理，并补入正文第 3–5 节新增记号。"
3. 两处译法必须一致——同一个 $\mathcal{D}$ 不能一处"数据集"一处"训练集"。

原文没有 Notation 节时，开头这张表就是唯一的符号约定，更要写全。

## 5 脚本怎么配合

```bash
# 1) 从原文抽候选符号，生成待填 CSV（按首次出现排序，带频次与上下文）
python scripts/notation.py extract 原文.md -o _work/符号候选.csv

# 2) 补 meaning 列，再按 first_line 顺序抄进译文开头的符号一览

# 3) 译完后核对：正文用了但表里没有的、表里有但正文没有的、没包 $ 的
python scripts/notation.py check 原文.md 译文_zh.md --csv _work/符号缺漏.csv
```

`extract` 抽的是"原子"：`x_i^{(t)}` 的原子是 `x`，`\sigma` 是 `\sigma`，`\mathbb{E}` 是 `\mathbb{E}`。所以 `x_1`、`x_2`、`x_n` 归并成一行（表里写 $x_i$ 就够），而 `x`、`\hat{x}`、`\mathbf{x}` 不会被混为一谈——它们确实是三个不同的量。

`check` 报三类问题，处理方式不同：

- **缺失**（正文有、表里没有）：出现多次的必须补；只出现一次的可以先判断"是不是临时记号"。
- **多余**（表里有、正文没有）：多半是抄表时抄错了符号，或者表是从旧版本抄来的——逐个回正文核对，这类错误最伤读者。
- **未用 `$` 包裹**：渲染会掉上下标，直接补。

`check` 是建议性的，退出码默认 0；加 `--strict` 才在有问题时返回 1。

## 6 常见陷阱

| 现象 | 后果 | 处理 |
|---|---|---|
| `\hat{f}` 抄成 `\hat f` | 渲染一样，但源码不一致，后续批量替换会漏 | 统一带花括号 |
| `\epsilon` 与 `\varepsilon` 混用 | 读者以为是两个量 | 全文取原文用的那一个 |
| 把 `\mathcal{L}`（损失）与 `L`（Lipschitz 常数）并列写 | 两个不同的量看起来是一个 | 分行，注明范围 |
| 表中写 `$x$：输入`，正文写"特征向量 $x$" | 术语不一致 | 表里的用词照抄正文定义句 |
| 表格里直接写 `|x|` | 竖线被当列分隔符，整行塌掉 | `\|x\|` 或 `\Vert x\Vert` |
| 表中符号比正文多一个下标 | 表与正文指向不同的对象 | `notation.py check` 的"多余"一栏会抓到 |
| 长公式塞进表格单元格 | 单元格被撑破、无法换行 | 表里只写符号与一句话定义，公式放正文 |
| 符号表放在文末 | 读者读到第 5 页时找不到 | 必须在正文之前 |

## 7 最小可接受版本

时间紧、符号极多时，允许的最小版本是：**只列反复出现、且定义句不在同一页的符号**，三列齐全，放在正文之前，用标记包住。宁可少列几个，也不要列错一个——列错比不列危害大，因为读者会信它。
