# 准确性规则

这份文件回答"这一处该怎么处理"，流程见 `SKILL.md`。所有条目都按同一条原则展开：**译文的信息量必须与原文严格相等**——不多一个解释，不少一个条件，不换一种写法。读起来顺不顺，排在这一条之后。

---

## 1 公式是不可改写的对象

### 1.1 保真的对象是 LaTeX 源码，不是"数学上等价"

等价改写看起来无害，实际是把作者的写法换成了你的写法。读者拿这篇译文去做推导、复现代码、核对证明时，差的是符号不是意思。

| 原文 | 不许写成 | 为什么 |
|---|---|---|
| `\log n` | `\ln n` | 底数不同；论文里 `\log` 的底常由上下文约定 |
| `\exp(-\lambda x)` | `e^{-\lambda x}` | 形式变了，指数函数的记号是作者选定的 |
| `\epsilon` | `\varepsilon` | 两个字形，同一篇里混用会被当成两个量 |
| `\partial_t u` | `d_t u` | 偏导与全导不同 |
| `\|x\|_2` | `\|x\|` | 范数下标是定义的一部分 |
| `\|x\|` | `|x|` | 向量范数与绝对值不同 |
| `x^\top` | `x^T` | 转置的写法在同一篇里必须统一，统一成原文那种 |
| `\subset` | `\subseteq` | 真包含与包含 |
| `x \le y` | `x < y` | 一个等号之差，定理的适用范围就变了 |
| `\mathcal{O}(n)` | `O(n)` | 花体与大写是两种记号；`\tilde{\mathcal{O}}` 另有含义（忽略对数因子） |
| `\{0,1\}^d` | `{0,1}^d` | 花括号必须转义，渲染错了整条式子读不出来 |
| `\mathbb{E}` | `E` | 期望的字体是有信息量的（区分经验期望与总体期望时常用） |
| `\mathrm{Var}` | `Var` | 正体与斜体：斜体 `Var` 会被读成 V·a·r |

允许改的只有空白与换行：多行公式的缩进、`$$` 前后的空行、`align` 里各行的对齐。定界符统一（`\[…\]` → `$$…$$`）由 `normalize_math.py` 机械完成，不靠手改。

### 1.2 不要在数学模式里加中文

`$...$` 与 `$$...$$` 里除了原文本来就有的 `\text{…}`，一律不出现中文。数学模式里的中文很多渲染器排不出来，而且一加就改变了公式内容。

`\text{…}` 里若是说明性文字（`\text{training loss}`），译成中文可以，但要一起改并接受 `math_fidelity.py` 的标记——它会把这类差异单独归为"文内文字不同"，不算公式改写。同一篇里要么全译要么全留，不要一半一半。

### 1.3 符号不得"统一"

同一个字母在论文不同位置指不同对象，是常态而不是疏漏：

- $x$ 在第 2 节是输入样本，在第 5 节是协变量；
- $T$ 在第 3 节是迭代步数，在附录是转置；
- $\lambda$ 在损失函数里是正则系数，在测度论附录是勒贝格测度。

不要为了"看起来整齐"把它们改成不同字母，也不要反过来说"这里重复了，合成一个"。符号冲突确实影响阅读时，写进待校对清单让人决定。

### 1.4 上下标的位置各有含义

`x_i^{(t)}` 三个位置分别是：个体 $i$、第 $t$ 次迭代。少一个、挪一个，意思就变了。

- `_t` 与 `^{(t)}` 不同（前者常是时间下标，后者是迭代层号）；
- `a_{ij}` 与 `a_{i,j}` 可能都是作者刻意写的；
- `W^{(l)}` 是第 $l$ 层的权重矩阵，简化成 `W` 就丢了层的区分；
- `\hat{y}` 与 `y` 是预测值与真值，互换即错。

### 1.5 公式编号是交叉引用的锚

`(3)`、`\tag{3}`、`式 (3)` 三处必须指向同一个公式。删掉一个公式、合并两个公式，后面的编号全会错位——这比译错一个词更难被发现，因为读起来通顺。

原文用 `\tag` 还是手写 `(3)` 保持一致；`\label`/`\ref` 原样保留，`math_fidelity.py` 会核对两边的编号序列与 label 集合。

## 2 定理类陈述：条件与强度

定理的全部信息都在"什么条件、多强的结论"里。译错一个限定词，命题就不是同一个命题。

### 2.1 标签不得混用

| 原文 | 译文 | 说明 |
|---|---|---|
| Theorem | 定理 | |
| Proposition | 命题 | 译成"定理"等于抬高结论等级 |
| Lemma | 引理 | 辅助性结果 |
| Corollary | 推论 | |
| Claim | 断言 | 常指未加证明的小结论 |
| Definition | 定义 | |
| Assumption | 假设 | 编号 A1、A2 沿用原文 |
| Condition | 条件 | 与假设分开时不要合并 |
| Remark | 注 | 不译"评论" |
| Conjecture | 猜想 | 未证明，译成"定理"即错 |
| Proof | 证明 | |
| Algorithm | 算法 | |
| Example | 例 | 后接编号时写"例 2" |
| Fact | 事实 | 有的作者用它代替 Lemma，按标签原样译 |

### 2.2 量词与辖域

- `for all x` / `for every x` / `for any x` → 对任意 $x$。"any" 在否定句和条件句里有歧义（"if any" 是"若有"），按上下文定，不要一律"任意"。
- `there exists` → 存在；`there exists a unique` → 存在唯一的。丢"唯一"就是改结论。
- `for some` → 存在某个，不是"对某些"。
- `not all` ≠ `none`；`no more than` ≠ `less than`；`at most` ≠ `小于`；`at least` ≠ `大于`。
- `if` 与 `only if` 与 `if and only if` 三档，不能合并成"当……时"。

### 2.3 条件不得省略或弱化

下面这些成分在中文里很容易被顺手省掉，而它们都是条件：

| 类别 | 原文 | 必须落在译文里 |
|---|---|---|
| 范围 | for all $n \ge n_0$ | 对所有 $n \ge n_0$ |
| 范围 | in a neighborhood of $x_0$ | 在 $x_0$ 的某邻域内 |
| 范围 | on a compact set | 在紧集上 |
| 正则性 | bounded / Lipschitz / sub-Gaussian | 有界／Lipschitz／次高斯 |
| 正则性 | twice continuously differentiable | 二阶连续可微 |
| 线性代数 | full column rank | 列满秩 |
| 概率模式 | almost surely | 几乎必然 |
| 概率模式 | with probability at least $1-\delta$ | 以至少 $1-\delta$ 的概率 |
| 概率模式 | in expectation | 在期望意义下 |
| 概率模式 | in probability / in distribution | 依概率／依分布 |
| 依赖关系 | where $C$ depends only on $d$ | 其中 $C$ 只依赖于 $d$ |
| 依赖关系 | independent of $n$ | 与 $n$ 无关 |
| 均匀性 | uniformly over the class $\mathcal{F}$ | 在类 $\mathcal{F}$ 上一致地 |

"其中 $C$ 为常数"漏掉"只依赖于 $d$"，读者就无法判断这个界在 $d$ 增大时还成不成立。这类漏译在中文里读起来毫无破绽，是本节最需要警惕的一类。

### 2.4 结论强度

- 上界与下界：`upper bound` 上界、`matching lower bound` 相匹配的下界。只有两者都有，才谈得上"最优"。
- 常数因子：`up to a universal constant` → 至多相差一个通用常数；`up to a logarithmic factor` → 至多相差一个对数因子。省掉这半句，结论就从"至多差常数"变成"精确相等"。
- 速率与常数：`rate` 收敛速率、`constant` 常数。`optimal rate` 与 `optimal constant` 是两件事。
- 存在性与普适性：`there exists an estimator` 与 `any estimator` 结论方向相反。
- `if and only if` 不能弱化成 `if`；`necessary` 与 `sufficient` 不能互换。

### 2.5 证明的结构

- 不合并步骤、不跳过"显然"的中间推理（作者写了的都要译，作者没写的不补）。
- `without loss of generality` 不失一般性；`by symmetry` 由对称性；`by induction on $k$` 对 $k$ 归纳；`by contradiction` 反证。这些是证明的骨架，不是修饰语。
- 内部引用保持编号：`by Lemma 2.3` → 由引理 2.3，不写成"由上述引理"。
- 结尾的 `\square`、`This completes the proof.` 保留。
- 证明里出现的"设……""取……""令……"是构造，动词不能换成"假设……"。

## 3 数值、单位与表格

- **有效数字与量级不改**：$10^{-3}$、`1e-3`、`0.001` 是三种写法，各自保留；$2.5\times10^{4}$ 不写成 25000。
- **± 与括号**：`12.3 ± 0.4` 是标准差还是标准误，看表注；表注说什么就译什么，不改括号里的数字的含义。
- **显著性**：`* p < 0.05`、`**`、`***` 的数量与阈值原样；`†`、`‡` 这类标记保留。
- **百分比与百分点**：percentage point 是百分点，不是百分比。
- **区间开闭**：$[0,1]$、$(0,1)$、$[0,1)$ 的括号形状不能因为"看起来一样"而统一。
- **单位不换算**：GPU-hours、FLOPs、ms、GB 一律保留原文单位；`per epoch` 译"每轮次"，不改单位制。
- **表格**：表头译，数据列一个字符都不动；$\uparrow$ / $\downarrow$ 表示"越大越好／越小越好"时保留符号，可在表注里说明。
- **表格的位置可以变，内容不行**：PDF 把表放到页顶是排版，Markdown 里应移到正文首次引用「表 N」的段落之后（表注跟着走）。移动时行列、数值、单位、星号、多级表头一个字符都不改；用 `figures.py relocate` 执行，不要手工拖拽。

## 4 算法与代码

伪代码（Algorithm 环境）的每一部分都有固定角色：

- 步号 `1:`、`2:` 不变；
- `for`、`while`、`if`、`return` 的结构与缩进不变，关键字保留英文；
- 函数名、变量名、超参数名不改（`SGD(`、`\eta`、`batch_size`）；
- 注释可以译——那是给人读的说明，不是代码；
- `Require` / `Ensure` 译"输入／输出"，或按原文"要求／保证"，一篇之内统一。

代码块（```…```）整块不动，包括注释。代码就是代码，译了就跑不起来。

### 4.1 格式本身是内容

伪代码的可复现性全在**缩进**与**行序**上。所以下面五样和公式一样不可改：

| 要素 | 要求 | 常见破坏 |
|---|---|---|
| 围栏 | 一块一对三反引号，必须闭合 | 关栏漏写 → 其后正文全被当成代码，结构对账静默失效 |
| 语言标记 | 围栏后的 `text` / `python` / `r` 照抄 | 丢标记 → 编辑器里没有语法高亮，读者分不清伪代码与真代码 |
| 缩进 | 空格数与层级照原样 | 循环体顶格 → "哪几步在循环内"这个信息没了 |
| 行序与行数 | 一行一步，不合并不拆开 | `3: g_t = … 4: θ_t = …` 并成一行 → 引用"第 4 步"时查不到 |
| 块内字符 | 反斜杠、井号、美元符、下划线、竖线一律原样 | 顺手转义成 `\_`、`\#` → 代码不能跑，且 PDF 里印出反斜杠 |

空行的增删不算改（空行不承载信息），非空行一行都不能少。

### 4.1b MinerU 的算法框是 div

中文语料里 MinerU 常把算法框抽成 `<div class="mineru-algorithm" style="white-space: pre-wrap; font-family:monospace;">…</div>`。它和围栏代码块地位相同，规则也相同，只有两点不同：

- **必须保留 div 外壳与 `class`/`style`**：`md2tex.py` 靠 `mineru-algorithm` 认出它，删了就会被当正文排（标签还会印到纸上）；
- 里面的 `$…$` 是行内公式，照规则 1 逐字符不动，不要当代码原样输出。

步号、行序、缩进空格、`\leftarrow`/`foreach` 这类关键字仍按 4.1 的表处理。`fidelity_check.py` 把 div 当「算法框」单独数，块数与行数是硬校验。

### 4.2 行内代码也是代码

`` `np.random.seed(0)` ``、`` `--model vlm` ``、`` `attention_head` ``：反引号保留、内容不译、不拆句、不换标点。它和 `keep` 术语不是一回事——`keep` 是术语（译名未定），行内代码是可执行的串（译了就跑不起来）。

### 4.3 提取器把伪代码压成散文时要恢复

MinerU 常把算法框按阅读顺序排成散文（`Algorithm 10.4 (…). The … can be computed …`），步号与缩进全丢。此时源文自己就没有格式可保，**恢复版式**是唯一出路：回 PDF 看块内结构，按一步一行、缩进照原样写成围栏代码块（语言标记 `text`），内容一字不改，并在交付报告里记一句。这不是"增"——它恢复的是原文本来就有的版式，和补回被过滤的页底脚注同一性质。

判据：`fidelity_check.py` 会把行首 `Algorithm N` / `算法 N` 而没有围栏的位置列出来；这份清单清零，才算伪代码都进了代码块。

### 4.4 交付前的机械判据

```bash
python scripts/fidelity_check.py <stem>_原文.md <stem>_zh.md --glossary _work/<stem>_术语.csv --strict
```

- 块数不同、非空行数不同、围栏未闭合 → 硬性失败；
- 缩进或代码记号不同（注释差异已自动忽略）→ 建议性发现，逐条回原文看；
- 语言标记丢失 → 建议性发现。

PDF 侧再由 `verify_pdf.py` 核 `codeblock` 数与每块首行是否进了文本层。

## 5 引用与交叉引用

- 括号引用 `(Smith et al., 2020)`、数字引用 `[12]`、`\cite{...}`：逐字保留，不翻译、不改标点、不合并。
- 叙述式引用 `Smith et al. (2020) proposed`：人名可音译或保留，年份必须保留（`fidelity_check.py` 只核对年份）。
- 图表与章节引用要跟着译文编号走：`Figure 3` → 图 3，`Table 2` → 表 2，`Section 4.2` → 第 4.2 节，`Appendix B` → 附录 B，`Equation (7)` → 式 (7)，`Algorithm 1` → 算法 1。**引用文字不改编号、不改写法**；被引用对象搬到引用段落旁，但引用句本身不重写。
- 图表编号与公式编号仍是同一套锚：搬动图表不会改变编号，所以正文引用不用跟着改；若搬完发现"图 3"对不上图注，是图注丢了，不是编号变了。
- 参考文献条目整条保留原文，不译标题、不译作者。
- 脚注标记 `[^1]` 保留，脚注内容照译——脚注里常有条件（"此处假设 $X$ 与 $Y$ 独立"），漏译等于改条件。

## 6 术语与缩写

- **首现格式**：中文（English, ABBR），例如"大语言模型（large language model, LLM）"；后文统一用中文或缩写，不要中英混跳到第三轮。
- **专名保留**：模型名、数据集名、软件名、算法名不译（Transformer、ResNet、ImageNet、PyTorch、Adam）。`transformer` 作为通用架构名也保留，别写"变换器"。
- **学科分流**：同一个词在统计与深度学习里译法不同，见 `references/terminology.md` 的分流表（consistency、robust、kernel、inference、value 等）。
- **不造词（硬规则）**：**没有通行译法时一律保留英文原文**，不得直译、不得意译、不得"先译一个再括注原文"。**中文简述只能写在译文开头「保留英文术语一览」的简述列，正文一处都不许出现**——包括首次出现处的括注、同位语、`（即…）`／`（一种…）` 一类写法；简述不带原文没有的信息，正文与之后全文只用英文。判定为保留的词在术语表登记 `dst=@keep`、`kind=keep`。`fidelity_check.py` 的 `check_body_hygiene()` 会用简述列反查正文，命中即硬性失败（`--strict` 返回 1）。
- **保留就保留到底**：大小写、连字符、单复数、缩写与原文该处逐字符一致；同一个词定了保留英文，全文不许再冒出一个中文译名。术语表 `alt` 列记下禁止出现的中文写法，`fidelity_check.py` 会查。
- **有依据才译**：种子表 `status=已定`、权威名词表、中文教材稳定定名，三者之一才算依据。`待裁决` 且本篇找不到依据的，一律保留英文。

## 7 语体：保真项不动，句法归中文

这份 skill 与文学、社科翻译的差别在这里：**不追"雅"，但要求"不像译文"**。

### 7.1 信息层：不做的事

- 不合并句子，若原文两句是"条件—结论"，合成一句常把条件变成从句里的插入语。
- 不调换从句顺序，如果调换改变了条件的辖域或指代。
- 不把被动改主动，如果原文的施事是有意模糊的（"it is assumed that" 是"假定"，不是"我们假定"）。
- 不删重复。作者重复同一句限定是刻意的强调，译文重复。
- 不改逻辑连接词。`thus`、`hence`、`therefore`、`consequently` 指示推理方向，各自对应"因此""从而""于是"；反过来，原文没有因果也不许补"因此"。
- 不软化强度。`at most`、`with probability at least $1-\delta$`、`up to a constant`、`it is easy to see` 读起来不顺，是因为它们精确。
- 不改量词顺序、不把 `if`／`only if` 的辖域挪位、不把定义句改写成断言句。
- 不加译者按语、过渡句、"值得注意的是"。

### 7.2 句法层：必须做的事

旧口径把"语序照英文、长句不拆、名词化保留"列为"允许的翻译腔"，代价是整篇读不动。这四条现在反过来——它们是**必须处理的病灶**，处理方式见 [fluency.md](fluency.md)：

| 病灶 | 手法 |
|---|---|
| 一句套三个从句、读到句末忘了主语 | 在从句边界拆句，主语按需补出 |
| "对 X 的 Y 的估计"这类"的"字链 | 定语改谓语，或重铸成短句递进 |
| 名词化 + 虚动词（进行／加以／予以 + 名词） | 还原成动词 |
| 一段五六个 `it` `this`，指代悬空 | 还原成具体名词 |
| 状语一路后缀到句末 | 前移或另起一句 |
| `however`、`in particular` 嵌在主干中间 | 前置，或独立成短句 |

### 7.3 边界

**仍然允许的"生硬"只有两种**：术语密度高到无法化解（一句里三个 `keep` 术语）、原文本身在堆条件（`under assumptions A1–A5`）。这两种场合硬拆会把一个断言拆成几句，反而看不清条件与结论的对应。

**其余场合，把英文语序照搬过来算没译完，不算"忠实"。** 判据是读者的成本，不是句子的长度：中文读者不需要回看英文就能懂，才算译到位。

**不许为了流畅牺牲确定性**：`we say` / `is called` / `is defined as` 保持定义句式，`denote` 保持"记……为……"，`it is easy to see` 不要升格成"显然"（中文的"显然"是更强的断言，等于宣称无需证明）。

---

## 8 原文错误

原文的符号前后不一致、假设与证明对不上、编号跳号、公式漏了下标——**照原样译，然后在交付报告里写明位置与判断**。

不静默修正的理由：改了，这就不是译作而是你的版本，读者无法判断哪句是作者的、哪句是你的。唯一的例外是提取错误（MinerU 把 `O(n)` 读成 `0(n)`、把上下标压平），那不属于原文，按 PDF 改正并在报告里记下改了哪几处。
