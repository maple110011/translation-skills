# 马恩引文定位 · 接口使用说明

本工具以**后台服务**形态提供：一个常驻进程，对外暴露 HTTP 接口。
输入英文引文，返回《马克思恩格斯文集》中的中文译文、章次、页码。

**不含前端界面。** 网页、桌面工具、批处理脚本都通过这套接口接入。

最常用的用法不是「查一条」，而是**整篇 Markdown 一次处理**：把论文稿里十几处英文
马恩引文一次性换成文集译文、补上出处，并给出可核对的清单。见第三节。

> 当前只收录《资本论》三卷（文集第 5、6、7 卷），共 27 643 句。
> 其他卷未收录，查不到不等于引文有问题。

## 一、把服务跑起来

### Windows（最省事）

双击 `start_service.bat`。它会在后台拉起服务并自检，成功后显示：

```
[ok] Service is up:  http://127.0.0.1:8080/healthz
     LAN access:  http://<本机IP>:8080/healthz
```

- 换端口：`start_service.bat 9000`
- 停止：双击 `stop_service.bat`
- 日志：`logs\server.log`（错误另见 `logs\stderr.log`）

服务监听 `0.0.0.0`，**同一局域网的其他机器可直接访问**，无需在那台机器上装任何东西。

### 命令行（任意系统）

```bash
python server.py                        # 127.0.0.1:8080，仅本机
python server.py --host 0.0.0.0 --port 8080     # 局域网可访问
python server.py --token s3cret         # 要求 Authorization: Bearer s3cret
```

只需要 Python 3.8+，**无任何第三方依赖**。

### 开机自启 / 注销后仍运行（推荐给长期部署）

把下面这条注册成「任务计划程序」里的任务，勾选“不管用户是否登录都运行”：

```
程序：      pythonw.exe
参数：      server.py --host 0.0.0.0 --port 8080 --log logs\server.log --pid logs\marxref.pid
起始于：    E:\...\_marx_ref
```

比双击 bat 更稳：不依赖控制台窗口存活，重启后自动恢复。

## 二、接口

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/healthz` | 健康检查（免鉴权，给监控/负载均衡用） |
| GET | `/v1/meta` | 卷列表、句数、页码覆盖 |
| GET | `/v1/match?q=...&topk=3` | 单条查询，浏览器里能直接试 |
| POST | `/v1/match` | 单条查询 |
| POST | `/v1/match/batch` | 批量查询（一次最多 500 条） |
| POST | `/v1/quotes` | 只抽取 Markdown 里的英文引文，不做匹配 |
| POST | `/v1/article` | **整篇 Markdown：抽取 → 匹配 → 回填中文与出处** |
| GET | `/v1/openapi.json` | 机器可读的接口描述 |

CORS 全开，前端可直连。

### 单条

```bash
curl -X POST http://127.0.0.1:8080/v1/match \
  -H "Content-Type: application/json" \
  -d '{"text":"Force is the midwife of every old society pregnant with a new one.","topk":3}'
```

```json
{
  "query": "Force is the midwife of every old society pregnant with a new one.",
  "count": 1,
  "matches": [{
    "score": 1.0, "coverage": 1.0, "ngram": 1.0, "nq": 8,
    "vol": 5, "chapter": "第二十四章 所谓原始积累",
    "page": 862,
    "en": "Force is the midwife of every old society pregnant with a new one",
    "zh": "暴力是每一个孕育着新社会的旧社会的助产婆。",
    "unaligned": false, "numeric": "n/a", "warn": ""
  }]
}
```

### 批量

```json
POST /v1/match/batch
{"texts": ["...", "..."], "topk": 1, "volumes": [5, 6]}
```

返回 `{"count": N, "results": [{"query": "...", "matches": [...]}, ...]}`，顺序与输入一致。

### 字段说明

| 字段 | 说明 |
|---|---|
| `score` | 英文侧相似度 0—1。**不是**译文正确率 |
| `coverage` / `ngram` | 词覆盖 / 连续三词命中的比例，score 的两个分量 |
| `nq` | 查询的实词数。小于 4 时结果仅供参考 |
| `vol` / `chapter` | 文集卷次、章名 |
| `page` | 印刷页码。`null` 表示该段没锚定上，需人工翻 |
| `en` / `zh` | 命中的英文句、**候选**中文译文 |
| `unaligned` | `true` = 这句没配上中文，`zh` 与 `page` 都不可信 |
| `numeric` | `ok` / `mismatch` / `n/a`：引文里的数字与中文句是否对得上。`mismatch` 多半是配错了段 |
| `warn` | 可直接展示给用户的提示语，可能为空 |

## 三、整篇 Markdown（主要用法）

译一篇论文时，稿子里十几处马恩引文要一并换成文集译文并补上出处。这是最主要的场景，
所以给了文章级端点，不必逐条调 `/v1/match`。

### 3.1 一次调用

```json
POST /v1/article
{"markdown": "<整篇 Markdown 原文>", "mode": "annotate"}
```

返回：

```json
{
  "stats": {"quotes": 7, "ok": 5, "review": 0, "unmatched": 2, "inserted": 5},
  "annotated": "<回填好的整篇 Markdown>",
  "items": [{
    "index": 1, "line": 8, "kind": "inline",
    "quote": "presents itself as an immense accumulation of commodities...",
    "status": "ok", "reason": "",
    "vol": 5, "chapter": "第一章 商品", "page": 47, "score": 1.0,
    "zh": "资本主义生产方式占统治地位的社会的财富，表现为“庞大的商品堆积”……",
    "unaligned": false, "numeric": "n/a"
  }]
}
```

### 3.2 两种模式

| 模式 | 行为 | 适用 |
|---|---|---|
| `annotate`（默认） | 保留英文原句，在后面追加 `【中译】“中文”（出处）` | 先看一遍再决定 |
| `replace` | 直接用 `“中文”（出处）` 替换英文原句 | 定稿 |

引用块（`>`）会在块尾追加一行，行内引号则在引号后接一段：

```markdown
> The wealth of those societies in which the capitalist mode of production prevails...
> （MECW 35: 125）
> 【中译】“资本主义生产方式占统治地位的社会的财富，表现为“庞大的商品堆积”……（《马克思恩格斯文集》第5卷，第47页）

马克思写道，"presents itself as an immense accumulation of commodities" 【中译】“资本主义生产方式……（《马克思恩格斯文集》第5卷，第47页）”（MECW 35: 125）。
```

### 3.3 三种状态

| status | 含义 | 后果 |
|---|---|---|
| `ok` | 命中且无疑点 | 回填 `【中译】` |
| `review` | 命中但有可疑信号（未对齐 / 数字对不上 / 引文过短 / 匹配度偏低） | 回填 `【中译待核】` 并写明原因 |
| `unmatched` | 未命中 | **原文不动**，只进清单 |

`unmatched` 多半是引了未收录的著作（第 1—4、8—10 卷），或根本不是马恩引文。

### 3.4 幂等

已经标过 `【中译】`/`【中译待核】` 的位置会跳过，同一篇重复处理不会插两遍。

### 3.5 先看会抓什么

```json
POST /v1/quotes
{"markdown": "..."}
```

只返回抽到的引文（行号、类型、文本、原文里的引用串），不做匹配。
稿子格式多变时，先跑这一步确认没漏抓、没错抓。

抽取会跳过：代码块与行内代码、HTML 注释、YAML front matter、已含中文的引文。
引用串（`MECW 35: 125`、`Capital III, p. 616`）会单独抽出来放进 `citation_in_doc`；
块引用里独占一行的那种也认。

### 3.6 命令行（不起服务也能用）

```bash
python article.py paper.md                   # → paper.zh.md + paper.report/
python article.py paper.md --mode replace    # 直接替换英文
python article.py paper.md --report out/     # 报告目录
```

`paper.report/` 下两个文件：`report.json`（全量，含偏移与匹配细节）、
`report.csv`（给人核对的清单：序号 / 状态 / 行号 / 英文 / 中文 / 卷 / 页 / 匹配度 / 说明）。
**定稿前把这份 CSV 过一遍**，尤其 `review` 和 `ok` 里中文明显跑题的条目。

一篇 7 处引文的稿子，整篇处理约 25 ms。

## 四、结果怎么读（做前端的话，这段最要紧）

返回的三样东西，**可信度不一样**：

| | 可信度 | 说明 |
|---|---|---|
| 卷、章 | 高 | 结构映射，基本可靠 |
| 页码 | 较高 | 从各卷 PDF 印刷页码逐段锚定，抽查 88/89 在 ±1 页内 |
| **中文译文** | **中等** | 句级自动配对，约四分之一会错位——**这是候选，不是结论** |

因此前端**必须**把 `unaligned`、`numeric`、`warn` 展示出来，不能只显示 `score`。
建议的展示规则：

| 条件 | 展示 |
|---|---|
| `unaligned = true` | 中文位置显示「该句未对齐到中文，需人工核对」，**隐藏或灰化「复制出处」** |
| `numeric = "mismatch"` | 醒目提示「引文中的数字与中文句对不上，很可能配错了段」 |
| `nq < 4` | 提示「引文过短，仅作候选参考」 |
| `score < 0.55` | 提示「匹配度偏低，多为两边段落划分错开所致」 |
| `page = null` | 页码处显示「页码待核」 |

> **真实的失败例子**：查 `Capital is dead labour, that, vampire-like, only lives by sucking living labour`，
> 返回 `score = 1.00`，但 `zh` 是另一段的句子，页码 270 也跟着错。
> 这句没有数字、没有专名，纯结构方法发现不了，上面几个信号都不会响——**只能靠在界面上提示用户核对**。
> 所以别让界面给人「系统已经确认」的观感。

## 五、性能（本机实测，73202 句）

| 场景 | 结果 |
|---|---|
| 单条 `topk=3` | 中位 15 ms，p90 31 ms |
| 批量 100 条 | 0.17 s（约 2 ms/条） |
| 8 并发 × 20 条 | 151 qps |
| 启动加载索引 | 约 1.3 s |

一篇文章十几处引用，批量一次调完，耗时在毫秒级。并发不需要额外配置。

## 六、配置项

| 参数 | 环境变量 | 默认 | 说明 |
|---|---|---|---|
| `--host` | `MARXREF_HOST` | 127.0.0.1 | 局域网共享用 0.0.0.0 |
| `--port` | `MARXREF_PORT` | 8080 | |
| `--token` | `MARXREF_TOKEN` | 无 | 非空则校验 Bearer token；`/healthz` 始终免鉴权 |
| `--max-batch` | `MARXREF_MAX_BATCH` | 500 | 单次批量上限，超出返回 413 |
| `--corpus` | `MARXREF_CORPUS` | 同级 `corpus/` | 语料目录 |
| `--log` | `MARXREF_LOG` | 仅 stderr | 追加写入日志文件 |
| `--pid` | — | 无 | 写 PID 文件，供停止脚本使用 |

错误一律返回 JSON：`400` 参数问题、`401` 未鉴权、`404` 路径不存在、`413` 批量超限、`500` 内部错误。

## 七、数据覆盖与已知边界

| 卷 | 内容 | 句数 | 配对率 | 页码抽检 ±1 页 |
|---|---|---|---|---|
| 第 1 卷 | 1843—1848 年著作 | 12712 | 88% | 49/49 |
| 第 2 卷 | 1848—1859 年著作 | 8515 | 93% | 53/54 |
| 第 3 卷 | 1864—1883 年著作 | 6858 | 89% | 46/50 |
| 第 4 卷 | 1884—1895 年著作 | 6269 | 93% | 49/49 |
| 第 5 卷 | 《资本论》第一卷 | 8931 | 92% | 41/44 |
| 第 6 卷 | 《资本论》第二卷 资本的流通过程 | 7126 | 93% | 45/46 |
| 第 7 卷 | 《资本论》第三卷 资本主义生产的总过程 | 11586 | 91% | 40/41 |
| 第 10 卷 | 书信选编 | 11205 | 75% | 38/40 |

**共 8 卷、73202 句。** 已配对的句子都带印刷页码；抽查 361/373 落在真实页码 ±1 页内（96.8%）。

没收录的两卷：

- **第 9 卷**（《反杜林论》《自然辩证法》）：语料仓库里没有可用的 HTML，只能从 OCR 质量较差的
  PDF 提取，暂缓。
- **第 8 卷**（《资本论》手稿选编）：它是**摘选**，一段中文对应英文手稿任意位置的一小段，
  小标题是编译局后加的，英文里没有；这组手稿又几乎没有数字可锚（567 段里只有 40 段带数字）。
  试了三种对齐方案都通不过抽检，**宁可不提供，也不给错的中文**。
  引《大纲》《1861—1863 年手稿》的，目前查不到属正常。

**「配对率」不等于「正确率」。** 配对率只说明句子配上了一个中文句。用数字锚独立检验
（2960 个含两个以上数字的句子）：62.3% 数字完全一致，12% 部分一致，26% 中文句里没有这些数字。
保守估计**四分之一的中文句存在错位风险**。

第 10 卷配对率只有 75%，明显低于其他卷——同一天有多封信时只能靠发信人和篇幅推测，会错配。
引用书信请对照 PDF 原书核一下。

其余两点：

- 英文底本是 MECW。若你引的是 Penguin / NLR 等译本，措辞不同，改写较多的引文可能匹配不上，
  把引文缩短到核心句通常能命中。
- 第 7 卷 Ch.29（银行资本的组成部分）没找到中文对应，该章引文会命中英文但中文为空。

## 八、想请大家反馈什么

**1. 覆盖面**：你手头译的东西主要引哪几部著作？（决定下一步扩哪卷）

**2. 命中质量**：随手试 10 条熟悉的引文，中文句大概几条对？把「错得最离谱」的发我，
比说「不好用」有用得多。

**3. 接口够不够**：现在给卷/章/页/中文句/匹配度 + 两个可疑标记。前端还需要什么？
例如：前后文段落、页码范围、整段而非单句、多候选并列、直接生成脚注格式、批量输入去重。

**4. 你的接入形态**：浏览器直连、后端转发，还是离线批处理？需不需要鉴权、限流，
或者把语料集中到一台机器上共享？
